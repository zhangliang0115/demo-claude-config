# 内部动作：handoff

只用于实际导出/交出材料，不注册用户命令。沿用已加载的 entry-workflow.md；同人同会话续作不制造自我交接。

## 仅导出已有材料的最短路径

明确任务目录已给出且本轮未要求继续实施时：

1. 用现成 CLI 核对当前事实和资料时效一次：
   ```sh
   python3 "${CLAUDE_PLUGIN_ROOT}/scripts/reviewable.py" locate "<明确任务绝对目录>"
   ```
2. 直接导出固定交接包：
   ```sh
   python3 "${CLAUDE_PLUGIN_ROOT}/scripts/reviewable.py" handoff "<同一任务绝对目录>"
   ```
3. 命令成功后以返回的真实 HANDOFF.md 路径交付，概述目标、当前结论和剩余缺口，结束本轮。不为导出新建 roles/handoffs、accepted 或验收记录，不要求先补 HTML。

该路径不要求先 ls、读脚本源码、搜索 schema、执行 --help 或重读已足够的源码。只有 CLI 实际报错、身份/资料不全或用户要求更新内容时，才针对问题补查，不用通用流程无限延长导出。需要关联本会话时按入口短路径处理，不把关联本身变成另一轮开发。

## 确需更新交接内容时

读取当前记录与必要源码，复述全局目标、本轮范围、契约、版本和第一步。仅在实际角色责任发生变化时读 team-workflow.md 并更新适用的 roles/handoffs，接收方未确认不标 accepted，AI 来源如实记录。重要事实仍 locate → 临时完整 JSON → CAS update，保存后再导出。

运行环境检查只在本轮接手依赖服务或声称服务正在运行时进行，且限已授权范围；离线材料/源码分析交接不启动服务、不查端口、不追加业务验证。历史成功不代表当前状态；源码、证据和接手版本不一致时先说明差异。

交接包保留生成区外的人工笔记，旧格式由脚本备份。HTML 仅在复杂材料确有阅读价值或明确要求时生成/复用；未生成或过期照实说明。复制反馈不自动批准或发布，不从交接包继承旧会话或另一机器的权限。
