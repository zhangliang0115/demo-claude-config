# 报告发布与并发保护

本页所称发布，是将生成结果写入本地 HTML 文件。0.17.1 将“准备报告”和“发布当前报告”分开核对。任务仍保存于原 task.json/feature.json，用户仍通过 go/status 工作；不增加每轮产出要求或新用户命令。

## 保护什么

- task 报告：拒绝旧任务记录、旧代码/行为指纹或旧证据评估覆盖 report.html。
- feature 总览：同时核对整体记录、项目关联及子任务实时评估，不能只比较共享契约版本或 feature.json。
- 同时生成：核对生成开始时的 HTML 与发布时 HTML，另一方已更新页面时，不让晚到输出覆盖它。
- 候选快照：传入 render 的缓存数据须与自身 provenance、顶层版本及实际当前评估一致；改正文但保留版本字段不能通过。
- 写入失败或冲突：保留已有 HTML 和事实记录，清理本轮临时输出；不改绑证据、不自动重跑业务。

## 发布顺序

```text
读取事实快照与当前 HTML 版本
→ 使用固定模板准备输出
→ 获取与同类事实更新共用的协作锁
→ 核对候选自洽、当前事实/评估、HTML 是否变化
→ 写入临时文件
→ replace 前再次核对
→ 原子发布当前报告，或明确拒绝冲突
```

任务报告与 update 共用 .task-update.lock；整体报告与 feature update/sync 共用 .feature-update.lock。锁是协作 CLI 的约定，不能拦截任意编辑器或旧版本客户端直接写文件。

已有同事实版本的有效页面时，缓存状态渲染可复用当前页面，避免旧 generated_at 回写。普通显式 render 的行为保持兼容；这不等于已实现所有无变化情况下的渲染幂等，也不代替模板版本管理。

## Agent 如何处理结果

- 发布成功才返回“本轮报告已生成”；路径存在不等于页面当前。
- 冲突时先说明报告未发布，必要事实若已保存应分别说明，不将两者混成全部工作失败。
- 用只读 locate/status 核对最新事实及报告时效；若已有有效新报告，可以复用并明确说明。
- 仍需新页面时，重新读取当前状态后再按需生成；不能用旧 state 强写，不能形成无限重试或为此重跑业务验证。
- 普通问答、恢复状态和内部步骤继续遵循按需产出策略；status 与 continue --no-render 不会因保护机制补建或刷新页面。

## 保证边界

发布检查针对当时能观察到的版本，不能把多文件、多仓库、运行中服务和外部系统锁成一个事务。业务源码、日志或子任务可能由不共享父锁的操作继续修改；之后报告仍可能过期，需按原规则核对 report_state。

保护适用于遵循新发布协议的客户端。旧版本 render、不遵守锁的直接编辑、任意本地写入以及校验后的未来变化，不在强制排除范围内；各会话应重载更新后的插件。没有 fcntl 的平台拒绝受保护发布，已有报告及只读查询不因此被修改。

本轮不部署报告服务、不建立审批后台、不自动归档业务版本，也不赋予新的生产或发布授权。
