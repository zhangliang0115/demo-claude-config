# 成本采样与初始基线

此页用于维护插件的评测，不属于日常任务必读资料。不添加用户命令、不安装后台追踪、不在每轮对话收集成本，也不自动把聊天全文写进任务。业务使用仍是 go/status。

## 先明确口径

| 指标 | 具体来源 | 不能推断什么 |
| --- | --- | --- |
| 本次 reported usage | 单个 Claude CLI result.usage | 不代表插件单独消耗；不与逐消息 usage 重复求和 |
| modelUsage / total_cost_usd | CLI 报告的模型/会话口径 | 续聊可能累计，不能当本次增量或账单；代理模型 costBasis 未知时尤其不能估算实付 |
| Read 返回量 | 实际工具返回的文本片段与行信息 | 不等于整个文件读取量或总磁盘 IO |
| Write 请求体 | 工具请求 content 的 UTF-8 字节 | 不证明写入成功，也不等于 token；Bash 写入不一定覆盖 |
| 工具返回量 | 实际观察到的 tool_result 文本 | 不等于模型完整上下文或输入 token |
| render / update 等尝试 | 可识别的工具调用 | 复杂 shell 标未知；进程成功与实际文件变化另核对 |
| 文件变化 | 调用前后 SHA、mtime、大小及任务字段差异 | 不能反推执行了几次写入、总读写流量或业务成功 |
| 交付时间 | 控制器 wall-clock 与 CLI reported duration | 不等于人理解时间，不把模型/工具/网络各段在缺数据时强行归因 |

缓存读取、缓存创建、普通输入、输出、思考等字段分别保留。不把嵌套 thinking/cache 子字段再次加进总数。missing usage 用 null/未知，不填 0。续聊中 modelUsage 与总金额可能包含前次请求，本轮对照使用全新 session，仍保留原字段口径。

## 固定第一批场景

固定同机、同用户配置的两个版本：0.16.0（a329f16）和 0.20.0（b53d4a2），分别从本地 Git 固定提交提取，不改用户工作区或安装目录。

1. 已有任务只看进度与下一步，不推进实施。
2. 仅在 summary 末尾补充一句说明并保存，不改行为约定。
3. 索要已有有效报告，不继续开发。

各版本/场景独立项目、任务、新 session，先由控制器准备相同业务语义和已有 HTML；初始化/准备时间单列，不混入模型交流。每场景一对，交错旧/新运行顺序，不先全跑一版。该首批只有六次样本，不代表统计分布或长期收益；失败、超时和缺数据全部保留，不挑成功补跑。

固定的 max-turns 和进程 timeout 只是工作量边界，不是精确 token 或金额预算。实际 num_turns 可与请求值不同，按原值记录。运行不覆盖用户模型、全局设置或价格，不启动业务服务，不进行业务测试或生产操作。

## 可复跑方式

维护者从包含两个固定提交的源码 Git checkout 准备私有输出目录，再明确启动六次模型调用；prepare 默认以脚本所在源码仓库为来源，不自动联网取提交。安装缓存不含 Git 对象，不能直接在缓存运行 prepare；run 和离线汇总既有输出不依赖源码 Git 对象。准备本身不启动模型。具体参数以脚本 --help 为准。

```sh
# NEW-RUN 必须是尚不存在的目录，父目录已存在。
python3 "/源码仓库绝对路径/zl-dev/scripts/evaluate_cost.py" prepare --output "/明确的私有输出目录/NEW-RUN"
# 此步才会实际启动六次真实模型调用；不因为有prepare就自动执行。
python3 "/源码仓库绝对路径/zl-dev/scripts/evaluate_cost.py" run --output "/明确的私有输出目录/NEW-RUN" --confirm-runs 6
# 已有轨迹可独立汇总，输出也必须是新文件。
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/cost_metrics.py" summarize "/轨迹目录/events.jsonl" --output "/轨迹目录/metrics.json"
```

prepare 与 run 都不能覆盖已有结果；运行中断不自动选择性重跑，先保留实际失败。重做整组时创建新的私有目录。原始轨迹包含项目路径与环境信息，保存在用户指定的私有目录，不提交公开仓库。只读分析器可以单独汇总已有 JSONL，不会执行日志里的命令。

评测必须验证实际 init 的 zl-dev 内联路径/版本，并记录 Claude 版本、模型、其他插件、工具及上下文来源的摘要。--tools/allowedTools 不等于隔离环境，实际仍可能加载全局插件与 MCP；比较时不能把全部 startup 成本都归给 zl-dev。无稳定环境或结果不等价时，不计算推广性的节省比例。

## 如何用结果决定后续

先检查每个样本是否完成同一目标、是否保留旧证据和权限边界，再比较同一口径的指标。单样本用于定位：重复读取是否明显、工具输出是否很大、全量 JSON 是否频繁往返、报告写入是否本可复用。

只有实测表明全量记录传输是主要问题时再做 ZL-12 增量更新；不能因为 JSON 看起来长就跳过 CAS、schema 或历史保护。样本少、缓存不一致、模型额外绕路或计价未知时保留不确定性，不写统一节省百分比。

第一批实测与解释见[2026-10-26 初始回放](../../docs/zl-dev/evaluations/2026-10-26-cost-baseline.md)。目前应优先核对入口材料与重复查询，不以单样本直接立项通用增量更新平台。
