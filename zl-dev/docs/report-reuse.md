# 报告复用与模板时效

用户仍使用 go/status。事实保存、业务验证和报告生成分开；普通交流不会因本功能自动生成 HTML。

## 什么时候复用

显式请求 render 时，只有以下条件均满足才保留现有文件：

- 任务/整体功能身份与精确记录版本相同。
- 当前代码、来源或回执等派生评估适用，能够核对代码版本。
- 展示模板版本一致，实际 HTML 与固定渲染结果一致。

满足条件时返回原路径，保持字节、文件修改时间和原 generated_at。生成时间表示该报告版本的生成时间，不伪装成此次查询时间。调用 render 返回路径不等于发生了新写入；对人说明“复用当前报告”即可。

缺失报告、事实/评估变化、模板变化或页面内容不一致时，确需页面才按当前输入重新生成。没有可核对代码指纹时继续 unknown，不能仅因模板已知就声称当前，也不把未知报告作为可信同版复用。

## 业务版本与展示版本分开

业务事实继续使用原 task_revision / feature_revision、current_fingerprint 与 assessment_revision。HTML 的 provenance.template_revision 另外携带展示模板版本，不写回 task.json/feature.json，不加入子任务业务评估，不改绑证据，也不会自动重跑测试或补验收。

展示版本按实际使用的 HTML、CSS、JS 字节与对应渲染协议计算。任务页与功能总览分别列依赖；共享样式变化会影响两类页面，任务专用视图不使只用其他素材的功能模板单独失效。README、文档或描述性映射文件不是实际渲染依赖时不触发重生。路径使用插件内相对标识，相同素材不会因为安装到另一个目录而改变版本。

渲染协议是程序变换规则的显式版本；修改素材拼接顺序、占位符替换或其他变换逻辑时，维护者须升级对应协议。它不是对执行中 Python 程序的完整身份认证；升级插件后重载会话，长进程热替换不在自动保证内。schema/阶段目录若影响派生事实，仍按既有评估规则处理，不能都归为纯展示。

## status 与旧页

report_state 额外返回 template_revision（页面记录值）、current_template_revision（当前素材值）和 template_freshness。

status/locate 只读检查事实与模板，必要时在内存比对固定产物；不写文件、不跑业务、不生成报告。freshness 保留 current/stale/unknown/missing：

| 情况 | 对人的说明 |
| --- | --- |
| 事实、评估、模板和实际页面一致 | 当前有效，可复用 |
| 事实或展示素材已变化 | 历史快照，说明变化原因；需要页面时再生成 |
| 旧页没有展示版本、模板不可读或代码不可核对 | 无法确认当前，不冒称已更新 |
| 没有文件 | 尚未生成，不阻塞普通工作 |

反馈继续按任务/评估及明确业务内容核对；本轮不把纯展示版本变化变成新的接受授权或一律重验理由。若旧展示存在会影响判断的歧义，针对实际受影响内容说明并核对。

旧页面保留原路径，不自动改写。用户明确要求页面时才按当前规则升级；生成失败保留旧页。此功能不为 HANDOFF 模板新增版本管理，不把旧页面直接当新的接受依据。

## 生成与竞争

读取固定素材一次，用同一份字节计算版本并拼接页面。发布和复用之前均核对当前事实、素材版本与 HTML，原子替换之前再检查一次。模板在生成中变化，或另一写入者已发布不同内容时，拒绝旧候选并保留已有文件。比较仅忽略本轮生成时间差异，不能忽略业务日期或任意正文差异。

展示文件被修改但内嵌记录未变，也不能仅凭其声称的模板号复用或标 current。需要按需重建固定页面，不直接把手改 HTML 当事实来源。

协作锁和末次检查不能锁住其他编辑器或外部系统；检查完成后的未来变化仍可能使报告过期。复用不证明业务已运行、已接受或可发布。
