# 第三轮：客户导出权限修复与人工核验闭环

0.13.0 完成了状态、验证回执与人工展示的改进。插件回归 **122 项通过**；另以真实 Claude Code 会话修改并验证一个隔离的 CSV 导出服务，操作浏览器控件、复制反馈，并对真实回执做篡改反例。人工验收仍为 pending。

## 场景与预置反例

- 运营导出客户 CSV，应只包含本租户客户，并保留引号、换行和危险前缀转义。
- 基线函数遗漏租户过滤；A 导出包含 B 的 Bob。原有两项 CSV 测试可以全部通过。
- 任务预置一条明确标注为夹具的模型通过声明、一项 P1、一个按钮文案待决，并故意指定人工验收阅读阶段。
- 保留一条旧版 AI 测试角色的退回观察，不能当成人签字。未填的人工项目始终 pending。

## 实际执行

1. 控制器复现权限泄露，运行内部 verify：原两项测试解析通过，不能关闭 P1。有效阶段仍为审查，当前行动由 AI 处理，而非让人先选按钮文案。
2. Claude Code 加入租户隔离测试，先出现失败，再增加 tenant 过滤，三项单元测试通过。
3. 模型通过内部 verify 生成三项测试回执，并绑定 B1/B2/B3。它此前的两次调用分别停在“准备 verify”和“准备更新”，均未冒充闭环。
4. 一次恢复会话遭遇五次权限拒绝，保持旧任务。为测试实例补齐具体任务目录、插件目录及 Python 命令允许范围后，模型以 locate/update CAS 将 R1 标记 done，并引用当前回执；随后实际 render/status。未修改用户全局配置。
5. 控制器独立检查 A、B、未知租户的 HTTP 结果，以及六种危险前缀、中文、引号、换行。
6. 浏览器点击发现原服务仍缓存旧模块，返回 Bob。核对进程工作目录后重启隔离服务，再点击只返回 Alice。这证明源文件修复和运行态验证是两步。
7. 临时修改当前回执的 stderr.log：来源降为 invalid、状态 not_run，当前行动重新由 AI 处理。finally 恢复原始字节，核对状态恢复且 task.json 不变。
8. 验收页通过真实下拉框、输入框和复制按钮填写 AC1 草稿；系统剪贴板只含本次 AC1，不含旧观察、AC2/AC3。刷新后草稿清空，旧观察仍只读保留。
9. 控制器补齐修复后的标题、概述与实现说明，使用 CAS 更新，确认语义/代码指纹不变。没有替负责人决定 D1 或标记人工通过。

## 本轮修复的插件问题

| 问题 | 结果 |

| 人工核验缺少环境与入口 | 固定准备区显示命令、入口、基线和停止方法；HTML 不执行命令 |

| status 顶层仍显示旧阶段 | stage 使用派生阶段，recorded_stage 保留原文；只读不重写任务 |
| 人工决策的问题与建议重复 | 右栏问题与建议各出现一次，AI 阻塞仍保持优先 |
