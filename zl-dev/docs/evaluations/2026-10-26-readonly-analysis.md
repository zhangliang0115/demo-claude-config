# 只读分析分支评测 · 2026-10-26

## 范围与来源

本轮针对插件的分析流程和离线产物，不建设或扩展业务网站。测试控制器编写两个隔离 Git 仓库（admin-web、quote-api）及四个报价源码文件，提供明确只读问题；它们是合成业务场景，不能当真实业务反馈。没有启动项目、运行业务测试、调用业务 API 或查询数据库。只检查桌面网页。

## 真实 Claude Code

通过本机 Claude Code 的 --plugin-dir 加载开发中的插件，使用用户现有模型配置，不覆盖模型。首次会话读取四个文件、调用来源元数据工具、保存 analysis 记录并生成数据链路报告；CLI 返回 success，原始 num_turns 为 25，permission_denials 为空。随后 resume 同一会话核对独立复核意见，返回 success，num_turns 为 6。四个业务文件 SHA256 均未改变。工具授权不是业务执行的硬沙箱；未执行业务程序的结论来自实际调用记录与文件核对。

复核发现最终回复“数据库字段只有一个”和“唯一持久化来源”范围过大：SQL 同时用 sku 筛选，优惠服务内部来源未读。真实 Claude 已把结论限定为这四文件显式 SQL 读取的金额字段，并保留优惠实现、真实数据、HTTP 解析和运行行为的范围外断点。未读取的持久化不能被静态推断填补。开发期间评估结构变化曾使首次报告过期，最终修订报告已核对为 current，不把中间产物冒称最终当前版本。

业务逻辑模式的第二份报告由控制器依据相同真实文件生成，用于比较规则模板；不声称它是另一次 Claude 自动分析。数据链路模式由真实 Claude 生成。两种报告均无外部资源请求；专页可展开来源，不包含开发、验收或发布动作。

## 对抗检查与回归

控制器在真实分析完成后临时修改额外接口仓库的 service.py：主仓库指纹未变，分析切换 analysis_refresh，报告变 stale；旧快照渲染被拒绝且已有 HTML 字节保持。继续改动已过期文件会改变 assessment_revision；记录内原始来源 SHA 不被自动改绑。恢复原文件后报告重新 current。此操作属于控制器验证，不是 Claude 重新分析。

267 项插件回归全部通过，包含新增来源路径、非 Git / Git 忽略文件、过期后二次变化、无效 UTF-8 / 二进制变化、缺失材料、范围外断点、kind/focus 约束、分析拒绝 verify、分析子任务不能充当实施完成、双模板与注入转义。首次全量运行暴露旧测试把新增分析阶段当 feature 阶段遍历；修正测试只遍历原开发阶段，保留运行时类型约束，最终全量通过。

## 限制与下一步

来源 SHA 仅证明观察版本一致，不证明解释正确、业务合理或链路运行。源码元数据工具仅接受已明确范围中的 UTF-8 文本，最大 16 MiB；无法读取或超限时不能保证观察全部字节。哈希不能替代语义审查。旧九种任务的语义指纹结构保持兼容，但阶段目录变化可能让旧报告评估显示需重生。用户命令仍只有 go/status，HTML 按需生成。
