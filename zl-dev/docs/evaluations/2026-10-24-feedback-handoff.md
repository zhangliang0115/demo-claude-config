# 第四轮：旧页反馈、人工结果与跨工具接手

## 本轮修复

基线为 `6b75814`（0.13.0）。三个独立只读审查均复现了材料时效问题：只修改待决问题、选项或观察记录，行为指纹不变，旧报告仍被返回；重导交接包会覆盖人工补充；同版人工退回没有进入当前行动判断。

0.14.0 保持 go/status 两个用户入口，补齐这条闭环：

- 报告绑定精确 task_revision 与确定性 assessment_revision，locate/status 只读说明 current/stale/unknown/missing。业务代码指纹仍用于测试和人工观察的版本绑定，不把文案变化当成必须重新测试。
- 复制反馈带代码/行为、记录和评估版本。旧问题的判断不能充当对新问题的批准；缺版本的旧页明确未知。
- HANDOFF 使用生成区；区外人工说明保留。未知旧格式先逐字节备份，再在新包引用。内容采用派生当前行动和阻塞，不再将 raw stage 当作当前结论。
- 人明确回传后，result_status 记录 pass/fail/blocked/not_checked。本版人工退回或受阻交 AI；全部人工通过已记录后停止重复催验，但仍由负责人决定后续。历史、AI 角色、自由文本和 done 均不自动算人工通过。
- 当前人工退回会传播到跨项目快照，不能出现子项目退回而整体仍准备就绪。发布环境、阈值或停止条件变化也会使原核验结论过期，补写观察与授权说明不改行为指纹。
- 核验已记录的页面先展示结论，准备环境和更正草稿按需展开；自动化专项不再误标普通人工操作。

## 实际检查过程

1. 创建独立 Git 项目，复用已修复的客户 CSV 导出函数和三项单元测试。通过内部 verify 实际执行并解析 3/3；页面初始 current。
2. 用浏览器原生单选、输入和复制按钮生成按钮文案 D1 的反馈。只把当前任务 D1 改成是否包含归档客户，代码/行为指纹保持不变；记录版本变化，旧报告立即 stale。只读查询前后任务树哈希及 mtime 不变。
3. 用真实 Claude Code 核对这份反馈。前两次在 8/12 轮限制内未完成：组合命令触发测试工具权限拒绝，模型又反复读取脚本查字段。补齐接口直接输出两个版本，并缩短 status 的查询路径。
4. 第三次以一次绝对路径 locate 为入口完成答复：拒绝将旧文案选项用于新的归档规则，正确指出报告是历史快照，未写任务。它仍把 task_revision 的标签解释为“未直接提供”，尽管输出已有该字段。因此只认定本次拒绝旧反馈和只读成立，不声称模型解释完全准确或自主可靠。
5. 控制器在明确标注 demo 的合成任务里注入人工退回，验证当前行动交 AI、页面为待处理反馈；随后注入全部通过，验证保持 acceptance 阶段而显示人工核验已记录，不自动发布。**这些 human 来源标签是测试夹具，不是真实人工签字。**
6. 向旧格式 HANDOFF 写入 CRLF 人工说明，导出后核对备份原始字节；在新生成区之外添加测试范围限制和干扰性旧版本行，多次导出均保留，来源判断仅使用生成区。
7. 分别修改源码及真实 verify 日志：旧报告、交接包均 stale。日志变化时 task.json 和行为指纹不变，派生评估变化仍可识别。finally 恢复原始字节后状态恢复。
8. 浏览器核对退回页、已记录页和移动宽度，更正草稿默认折叠，原观察只读；真实任务的 0.13 报告先显示 unknown，显式重新生成后 current，未重写原任务数据。

## 结果与限制

完整插件回归 **158 项通过**，原始输出见本机归档 `plugin-unit.log`。新增测试覆盖版本字段、只读、旧报告和损坏报告、日志单独变化、人工与生成区隔离、写入失败保留原文、人工结果状态机及跨项目传播。plugin/marketplace manifest 校验单独记录，不等同官方目录上架审核。

- 只读状态不会修复报告。离线 HTML 不会自行轮询，也不能知道已经打开后外部文件是否变化。
- 这些哈希不是签名或身份认证；可写本地文件者仍可能联合伪造。人工标签须对照实际回传依据。
- 未引入反馈自动导入或审批服务；旧反馈处理仍依赖 AI 遵循核对规则，不能保证任意模型质量一致。
- 原子替换防止写入失败截断旧文件，不防外部编辑器并发写入。非 Git 项目或未知指纹不能标为已核对当前代码。
- 实际模型为用户配置的 `opendesign/deepseek-v4.1-flash[1m]`，Claude Code 2.1.309；没有做多模型对照，没有生产操作或真实业务验收。
