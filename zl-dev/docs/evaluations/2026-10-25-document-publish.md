# 企业文档审核发布：双项目、规则变更和真实 Claude Code 接手

本轮从合成业务需求构造可运行的管理端与接口项目，不要求已有生产项目。固定业务规则、失败条件与角色反馈，再运行代码、HTTP 和桌面浏览器；合成的是需求与角色输入，执行结果来自实际运行。真实人工验收仍 pending。

| 部分 | 执行来源 |

没有把 Codex 搭建夹具说成 Claude Code 从零实现全部业务，也没有把 HTTP 或浏览器测试冒充 Claude Code 调用。客户端是真实 Claude Code，但沿用本机配置的 `opendesign/deepseek-v4.1-flash[1m]` 模型路由；本轮不是 Anthropic 官方 Claude 模型的对照评测。

## 需求与中途变化

起点是“文档发布前要审核，发布后能修改，撤回能恢复，其余由 AI 提合理方案”。先提出作者、审核者、公开读者三个视角，整体约定后分配接口与管理端，两个项目均由同一开发者承担，不为项目数量制造多人签字。

合成负责人选择 v1：已发布文档编辑时暂时下线，重新审核后才公开。v2 中途改为：编辑形成新草稿，审核前读者继续看到旧已发布快照；草稿或待审期间仍可撤回旧快照，恢复只能恢复旧审核内容，不发布新稿。

禁止作者自审、审批绑定提交版本、幂等重放不重复审计，在 v1 已存在，属于保持项。Claude Code 曾将其中两项误述为 v2 新增；控制器指出矛盾后，它读取保留的 Git 历史进行了纠正。不能仅凭模型生成的前后对比认定版本历史。

## 真实执行结果

- v1 业务单测 **12/12**、独立 HTTP **12/12**。
- v2 业务单测 **17/17**、独立 HTTP **14/14**。
- 桌面原生控件 **13/13**，覆盖作者自审 403、独立审核、匿名公开读取、幂等重试、草稿保留旧公开内容、撤回恢复、重新审批及保存冲突保留输入。
- 控制器另行走了“审核退回→作者修订→重提→审核发布”的原生控件路径；随后通过重放入口再验证自审被拒、旧快照保持、新版独立审核发布。
- 新旧规则下的整体 preflight 均实际运行：约定未确认或项目版本未对齐时返回缺口，对齐后通过。它是流程检查，不是编辑拦截器。
- Claude Code 实际执行内部 verify，生成可重新解析的 17 项测试回执，并完成 locate/update CAS、render、HANDOFF 导出。环境准备资料更正后，旧回执保留为历史，又通过真实 Claude Code 新增回执，未改绑旧版本。
- 插件完整回归 **174 项通过**；manifest 校验独立记录，不等于官方目录上架审核。

首次 Claude Code 调用达到测试设定的轮数上限，续跑才完成记录闭环；最后一次定向重验虽然执行了验证、渲染和交接，但在最终答复前也达到轮数上限。原始失败与成功均保留，不能声称无人干预一次成功，更不能从一个场景推算可靠率。

## 场景实际暴露并修复的问题

1. **本轮变化藏在折叠材料中。** 桌面基线的两条变化在约一千五百像素处且位于关闭的详情中。现在直接展示既有 changes，最多三条，余项按需展开，空白与重复项过滤；不增加手填字段，不重复当前主要行动。实际桌面复测确认变化和当前行动同屏可见。此为机械阅读代理检查，未测量真人一分钟理解效率。
2. **跨项目旧页缺少精确版本核对。** 总方案补充功能记录和评估版本，复制反馈携带它们；locate/status 只读报告页面时效。只改设计说明、不改契约版本，旧页也会变 stale；子任务、代码或日志改变同样会使派生评估变化。
3. **复制版本可与页面来源不一致。** 任务页顶层用于复制的版本字段现在必须与 provenance 一致。缺少字段为未知、矛盾为过期；这不是签名或联合伪造防护。
4. **等价项目路径误伤真实回执。** macOS 的等价绝对路径或项目符号链接曾使执行成功的回执被误判无效；读取时改为规范化核对，仍拒绝不同项目，新增实际运行反例。

## 展示与使用边界

- 本轮只测桌面网页，不做手机尺寸检查。界面验证按用户要求的终端范围执行，不默认扩展设备矩阵。
- 原生角色切换使用测试请求头，不是生产登录、SSO 或完整认证方案。
- 实际权限检查、公开快照、事务与审计均在接口完成；页面只展示真实返回，未用编辑框内容冒充公开结果。
- 人工核验项保持 pending，AI 观察有明确来源，联调准备就绪不等于业务接受或发布批准。
- 本地哈希和解析回执不提供身份认证。离线报告也不会自行知道打开后外部数据是否变化。
- 语音结束前曾出现“已推送”的提前表述；当时尚未提交，实际发布只以最终 Git 提交及远程核对为准。

## 追加：用户委托 AI 代验

用户随后明确要求由 AI 代替人工做既定功能验收。两项标准通过真实桌面控件重新执行，初验发现此前检查遗漏的页面缺陷：公开接口已返回 404、列表已移除文档，阅读区却仍残留旧正文。因此先记录 AC2 退回、当前失败与审查阻塞，未直接宣布通过。

真实 Claude Code 在 portal 仓库加入实际执行 app.js 的 Node 回归，修复前五项中三项失败；最小修复后五项全部通过，覆盖撤回、新公开版本、切换、读取失败与未变化时保留有效正文。控制器另在真实网页复核撤回清除、恢复旧稿且新稿待审、审核后再读取新版，并在最终本地提交上通过 JUnit 回执重验五项，再关闭原阻塞。原失败记录保留为历史，没有改绑。

最终 AC1/AC2 均为 AI 代验通过，reviewer_kind 保持 ai，不伪造 human 签字。当前通用状态仍区分人工签字与 AI 记录；代验结论以同任务目录的 AI-ACCEPTANCE.md 为准，不表示用户必须重复本轮操作。生产发布未执行。原始代验、退回、Claude Code 修复、前后测试和浏览器复验归档于 `~/.claude/zl-dev/evaluations/2026-10-25-ai-acceptance/`。本次修复属于合成业务夹具；插件运行代码未变更。
