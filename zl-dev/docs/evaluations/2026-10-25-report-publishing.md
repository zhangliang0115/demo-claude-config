# 报告并发写入验证（0.17.1）

## 本轮实现

报告准备与写入分离，候选快照自洽校验、当前事实/评估核对、HTML 字节版本比较及 replace 前复核。task 与 update 共用任务锁；feature 与 update/sync 共用功能锁，并核对子任务实时评估。冲突保留已有 HTML 与事实记录，临时文件清理；不引入新的用户命令、自动生成或业务操作。

## 实测与结果

- 修改前用真实多进程构造：A 读旧快照等待，B 经 CAS 更新并生成新报告，再释放 A。旧 A 成功覆盖新页面，最终报告 stale，复现失败成立。
- 修改后用同一脚本：A 旧写入被拒绝，原新 HTML 字节与修改时间保留，最终 summary 为 new state、report_state=current、task.json 未再变化、临时文件为零。
- 另一个真实多进程 feature 场景：保持 feature.json 不变，更新关联子任务并生成新总览，再释放旧 writer。旧写入被拒绝，父 JSON/新 HTML 保留，页面匹配新子任务版本且 current。
- 独立审查额外在 feature 临时文件写完后改子任务 metadata 或子仓代码，两种情况均拒绝发布、保留原文件并清理临时文件。
- 新增 16 项发布专项通过；全量 230 项通过（42.631秒）；独立审查的16项针对测试通过。初次全量发现旧注入测试的 mock 模板未保留实际必需的 feature-data ID，补齐夹具后通过，未放宽快照验证。
- 回归涵盖伪造缓存快照/顶层版本、不匹配 provenance、准备期间事实变化、HTML 自身变化、末次校验、相同事实并发复用、写入失败清理、未知指纹、无 fcntl 平台与只读/延后生成兼容。

这是受控顺序的真实进程验证，不是并发压力测试；没有重新运行 Claude Code 业务全流程或搭建业务网站。临时输入为合成任务，用户真实任务未修改。

## 边界

新协议只能协调遵守锁的当前 CLI。旧缓存脚本、任意直接编辑及锁外的业务源码/日志/子任务变化，不能被父级锁全局阻止；发布后仍可能过期，需 status 核对。参与同任务的 Claude Code 会话应重载更新后的插件，不自动关闭用户会话。

没有实现模板版本管理或所有情况下的渲染幂等；缓存同事实页面复用不代表这些 TODO 已全部完成。没有 fcntl 时拒绝受保护发布，读取仍可用。
