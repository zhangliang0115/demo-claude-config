# 按场景组织页面（0.8.0）

统一视觉、组件和反馈协议；不同事项使用独立的页面结构，不用同一张表换标题。assets/views/ 存放真实渲染模块，templates/layouts.json 是路由说明。

- 新功能/业务调整：理解阶段先展示用户问题与故事；方案阶段先完整流程与候选方案；实施阶段先实际切片与变化；验收阶段先亲自操作和结果证据。
- Bug：症状、复现、原因依据、修复和回归。假设不能写成已证实根因。
- 生产事件：影响、时间线、事实与诊断假设、处置及恢复。保持运维优先，不展示产品需求流程。
- 日常运维：目标范围、操作顺序、停止与恢复、实际结果。
- 重构：行为不变量、结构改动、回归。
- 性能：同条件基线、目标和实际、瓶颈与代价；缺测量不画假图。
- 数据迁移：转换方案、预演、核对、恢复；不能把代码回滚等同数据恢复。
- 技术升级：兼容性、模块顺序、新旧对比、上线与回退。

共享页首只提示当前具体动作。各专用页直接读取已有事实字段；阶段扩展只有需要额外信息才填写。缺少资料显示对应缺口，不为了好看编造证据。当前阶段由 workflow_summary.focus_stage 或明确 focus_stage 决定，不能只根据中文 stage 文案猜测。

生成方式仍是 reviewable.py render，禁止 agent 绕过这些模块自行设计临时页面。共用 CSS 不代表共用信息结构。场景/阶段不适用的内容不挤进当前主页面，历史阶段保留在任务数据中，不在当前页面拼接。

## 紧凑视觉规范（0.9.0）
report-theme.css 是所有报告最后加载的共享视觉层：正文14px，适度行距；页头、卡片和表格收紧间距。桌面主内容与当前动作并排，手机单列；详情仍原位展开。各场景保留自己的信息结构，共用颜色、字体、密度和交互。不得在任务 HTML 中另写覆盖样式。

## 场景总览与阅读提示（0.10.0）
examples/index.html 是模拟场景入口，按读者要解决的问题分类并指向不同页面。使用 build_demo_gallery.py 统一生成；示例 tasks 可以有 demo: {category,purpose,read_order,simulation:true,order}。真实任务不填写 demo。报告首屏的阅读提示根据 kind/focus 计算，页内跳转只指向真实存在的专用内容；不使用空链接或占位流程。

## 单阶段工作页（0.11.0）

需要报告时直接打开当前任务 report.html，由 focus_stage 决定本次呈现的阶段。阶段推进先保存事实，有实际阅读需求时才更新同一页面；普通问答和简单结果可文字交付，不把需求、方案、实施、验收同时铺开。examples/index.html 仅是模拟示例目录，按阶段选择独立页面，不作为真实任务入口。报告采用连续文档与集中反馈栏，流程直接可读，反馈预览按需展开。

## 只读分析专页（0.18）

kind=analysis 使用 assets/views/analysis.js：business_logic 展示有序入口/流程与条件规则卡；data_flow 展示数据流转与字段映射表。共用问题与结论、事实/推断/未知、断点及源码依据，过期来源明确待重查；不展示通用实现、回滚、验收表，不发网络请求。报告按需生成，资料不足保持未知。
