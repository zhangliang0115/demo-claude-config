# ZL Dev 插件说明

## 基本信息

- 插件名：`zl-dev`
- 当前版本：`0.25.0`
- 类型：Claude Code 命令与代理插件，附带本地 HTML 生成工具
- 标准插件描述文件：`.claude-plugin/plugin.json`（相对于本插件目录）
- 仓库安装入口：仓库根目录 `.claude-plugin/marketplace.json`
- 运行依赖：Claude Code；Python 3.9+ 标准库。安全写入依赖 POSIX `fcntl` 文件锁；Windows 只读路径仅做模拟测试，尚未真机验证，写入暂不支持

## 解决什么问题

需求和设计由 AI 辅助产生，实施者可能换人、换工具、换模型，导致理解偏差和验收困难。本插件用固定结构记录目标、事实、假设、方案、接手复述、行为约定、实现与证据，并按需生成统一交互式 HTML，让人快速理解、处理决策和核验结果。

## 适用场景

新功能、业务规则调整、缺陷修复、重构、性能优化、数据迁移、技术升级、生产事件排查和日常运维。尤其适合需求尚不明确、多人分阶段交接、需要人工为最终结果负责的工作。

## 命令清单

- `/zl-dev:go`：新需求、继续工作、反馈、跨项目功能、排障均从这里进入。
- `/zl-dev:status`：只读查看当前任务、缺口及下一步。

设计、审查、测试等为内部按需指引，不再注册独立命令。

## 固定交互模板

任务事实保存于 `task.json`；确需结构化阅读或用户明确要求时才生成当前阶段的 `report.html`，按事项类型和阶段呈现目标、关键变化、待决事项与必要证据，不把全部阶段拼在一页。支持详情展开与填写反馈并复制给 AI；跨项目功能总览默认打开当前阶段，也支持本阶段反馈复制。场景模拟明确标注，不能作为真实运行证据。

## 产物与存储

默认写入用户目录 `~/.claude/zl-dev/projects/<项目名>-<路径哈希>/tasks/<slug>/`：
- `task.json`：结构化事实、方案、交接和证据记录。
- `report.html`：按需生成的离线交互页面，不是每轮必须产物。
- `HANDOFF.md`：其他人员和 agent 的接手说明。
- 必要的脱敏测试日志、截图等证据，由工作流按实际执行保存。

代码与行为约定指纹用于在重新渲染时提示旧证据过期。它不证明测试真实执行，也不覆盖外部系统或 Git 忽略文件。

## 状态与安全更新

`status` 通过只读 `locate/status` 查询，不创建目录或重写页面。既有记录经 `update` 校验绑定与 revision CAS 后原子替换；跨项目记录另校验派生快照不可手改。版本冲突拒绝覆盖，需重新读取合并。更新与渲染分开执行。

跨项目实施前的 `preflight` 核对共享契约与依赖版本，只是流程检查，不是工具级硬拦截。项目快照同时核对关联子任务身份，换绑后需重新同步；历史过期证据不单独阻塞就绪，当前未通过的证据仍会阻塞，不能用一次通过掩盖矛盾结果。

## 验证与人工核验

AI 优先使用内部 `reviewable.py verify` 执行现有 unittest/JUnit 检查并关联行为，保存命令、日志、解析结果和前后指纹；这不是新的用户命令。旧记录作为模型声明兼容保留，不能冒充解析回执。解析不能证明业务覆盖或执行者身份，也不是防篡改认证。

先确定验收环境、起始数据及结构化预期，再验证；人工页分开显示历史观察与本次草稿，不预选通过。`reviewer_kind=ai` 用于 AI 测试角色，不能冒充人工。`focus_stage` 是阅读偏好；当前未通过证据与未解决 P0/P1 优先。P0/P1 标记 done 后仍需引用当前、无矛盾的通过复查。

## 安装与使用

本地开发，在业务项目目录运行：
```sh
claude --plugin-dir /本仓库绝对路径/zl-dev
```

文件提交并推送至 GitHub 后：
```text
/plugin marketplace add https://github.com/zhangliang0115/demo-claude-config
/plugin install zl-dev@zl-dev-marketplace
```

入口示例：
```text
/zl-dev:go 我们希望减少客服处理取消订单的工作，具体规则还没确定
```

## 能力边界

- 不是线上审批服务、自动部署平台或生产命令执行器。
- 不会自动跨人同步、推送 Git、发布网页或替人批准。
- 页面反馈是草稿，需明确回传并核对版本后记录。
- 其他 agent 通过 HANDOFF.md 和 Python CLI 复用数据；不声称原生支持 Claude 插件命令。
- 固定模板约束交付结构，不能保证不同模型产生同等质量的需求和实现。
- 人保留关键业务取舍和新增行动范围的决定；可明确委托 AI 按标准验收，实际判断者始终如实记录。

更多说明：[README](README.md)、[团队工作协议](docs/team-workflow.md)、[数据格式](docs/schema-reference.md)。

## 阶段专用展示
“阶段工作台”按九个固定阶段呈现不同布局和交互。规则见 [阶段模板协议](docs/stage-templates.md)，字段以 `templates/stages.json` 为准；AI 不自行生成样式。

## 跨项目功能入口
`/zl-dev:go 跨项目`：先识别候选项目与现有职责，再整体设计、确认共同契约、分配项目切片和依赖，最后整体联调。实施可一人或多人；人员独立于项目边界。详见 [用法与示例](docs/cross-project.md)。

日常入口 `/zl-dev:go`：描述需求或反馈，AI 连续推进、及时保存重要事实，有实际阅读需要时才更新报告。设计、审查和测试使用内部按需指引，不再暴露独立阶段命令。

实际报告只展示当前阶段。examples/index.html 仅为插件演示目录，不是实际任务的工作入口。阶段变化先保存事实，按需更新同一 report.html 为新阶段，其他阶段的记录保留在数据中，不拼接展示。

## 报告时效与人工闭环（0.14）

locate/status 返回 report_state，路径存在不代表报告当前；记录与评估版本随反馈复制，代码/行为指纹继续绑定实际核验。HANDOFF 的生成区和人工区分离，旧格式先备份。明确的本版人工退回进入当前行动和跨项目阻塞；全部人工或明确受托 AI 验收通过后，不要求人重复同范围核验；后续沿用已有授权，不自动发布。

0.15.0 将本轮变化直接展示在当前阶段页，补齐跨项目报告的精确版本核对，并通过 [文档审核发布场景](../docs/zl-dev/evaluations/2026-10-25-document-publish.md) 实测规则变更、真实 Claude Code 接手和桌面控件。该轮插件回归174项通过，记录不包含人工签字。

0.16.0 将检查执行、结果接受与行动授权分开表达，支持明确委托下的 AI 验收，并取消已完成同范围核验的重复人工要求。详见[协作模型](docs/collaboration-model.md)与[本轮验证记录](../docs/zl-dev/evaluations/2026-10-25-collaboration-model.md)。

0.16.1 解除 go 的强制报告产出：默认创建/恢复使用内部 `--no-render`，事实保存与 HTML 分开；普通问答和内部步骤可文字交付，确需审阅材料或明确索要报告时才生成。旧无标志 CLI 行为保持兼容。

## 会话关联与多任务续作

长期任务与会话焦点分别保存。go 使用宿主会话标识、本项目作用范围和已核对目标建立恢复关联；明确新事项、切换和接手优先于旧焦点。status 只读查询，临时看另一目标不会切换。缺失/失效关联不猜唯一或最近任务；没有可靠宿主 ID 时使用明确路径。关联不授予权限、不隔离业务代码，也不自动创建 worktree。内部协议见[会话关联](docs/session-context.md)。

0.17.0 增加会话焦点关联：go 核对后绑定长期任务或整体功能，继续时按本会话、本项目恢复；status 只读且临时查看其他任务不切换焦点。缺少可靠 ID 或有效关联时不猜测，用户仍只用 go/status。关联不隔离业务代码或运行资源。详见[会话关联](docs/session-context.md)。

0.17.1 保护任务报告及跨项目总览的并发发布，冲突保留已有页面；已有客户端需重载新版本。保护不等于锁住业务代码、外部编辑器或跨项目全部数据。

## 只读业务逻辑与数据链路分析（0.18.0）

```text
/zl-dev:go 只读分析订单取消的条件、异常和退款分支，先不修改代码
/zl-dev:go 从页面实付金额追到接口计算和字段来源；范围为当前管理端及 /明确的接口项目路径
```

短问题直接引用源码回答；持续分析使用独立 analysis 记录。跨项目读取无需建立实施分工或确认开发契约。事实、推断、未知和断点分开保存，来源绑定文件、行号与真实哈希；文件变化时要求重新核对，不自动改绑旧结论。可继续追踪的断点交 AI，缺材料只问具体材料，范围外保留边界。

复杂分析需要审阅或明确要求时才生成离线 HTML：业务逻辑页突出条件与结果，数据链路页突出流转与字段映射；没有业务接口请求，也不要求开发、测试或验收签字。分析材料整理完不表示运行正确。详见[分析流程](docs/analysis-workflow.md)及[本轮评测](../docs/zl-dev/evaluations/2026-10-26-readonly-analysis.md)。

## 多会话执行工作区（0.19.0）

```text
/zl-dev:go 继续当前任务；先检查是否有其他任务正在修改同一份代码
/zl-dev:status 查看当前任务实际代码目录，以及已登记的并行活动
```

开始实施/验证前按需核对 checkout 并登记活动；同一份代码的两个写入或验证会提示冲突，只读可并行且保留变化风险。不同 worktree 可识别为同一本机 Git 仓库的不同 checkout，但端口、数据库等资源仍需明确核对。已有 write 内执行测试不重复申请 verify。

活动不授予权限、不拦截外部编辑器、不自动建 worktree，也不因超时自动释放。任务原路径和证据绑定保持原样；跨机器逻辑项目迁移、强制接管和证据迁移尚未实现。报告页脚可展开代码位置与代码/行为指纹。详见[执行上下文](docs/execution-context.md)。

## 提示词与续作收敛（0.19.1）

共用规则集中在 entry-workflow.md，go 和内部动作不重复抄录；当前版本已在上下文时不重复加载。schema、团队和阶段模板按实际缺口读取，历史设计快照不作为当前提示词。

仅切换焦点走 resolve/bind 短路径；仅导出已有交接材料走 locate/handoff，离线分析不查端口或启动服务。必要事实与安全校验保留，报告仍按需。

跨项目总览不固定要求人工重验，也不从子任务通过或自由文本推导整体接受；功能级整体验收自动聚合尚未实现。详见[本轮评测](../docs/zl-dev/evaluations/2026-10-26-prompt-consolidation.md)。

## 报告复用与模板时效（0.20.0）

事实、评估、模板和实际页面一致时，显式 render 也会复用原文件，保留修改时间和生成时间。展示模板变化会单独提示过期；更新页面不改任务事实、不使业务证据失效，也不重跑测试。旧页没有模板版本时保持 unknown，确需页面时再更新。

任务报告与跨项目总览均适用。status 仍只读，用户仍只用 go/status。详见[报告复用规则](docs/report-reuse.md)；长进程升级后需重载，新旧客户端混用不具备同等保护。

## 成本采样工具与初始基线（0.21.0）

新增维护用离线轨迹分析器及显式成本采样脚本，不新增日常命令、不自动追踪或启动模型。固定旧版与当前版的三组、六次真实会话已留档，模型 usage、缓存、工具输入/返回、文件变化和耗时分开记录；金额未知口径不当账单，字节不换算 token。

本轮是单样本初始基线，ZL-11 仍部分完成。工具调用减少不代表输入 token 全面降低，也未证明应该立即建设通用增量 JSON 引擎。维护者须从有历史提交的源码 Git checkout 准备采样，安装缓存不能直接 prepare；离线分析既有日志可独立使用。详见[采样方式](docs/cost-baseline.md)和[实测结果](../docs/zl-dev/evaluations/2026-10-26-cost-baseline.md)。

## 已有记录的短查询（0.22.0）

仅看进度、已有结论或报告时先读 quick-read，不加载完整工作协议。locate 额外返回有界业务目标预览，信息足够就结束；状态查询不改焦点、不改任务、不刷新过期页面。go 明确索要当前报告时，才按实际时效生成派生页面。

新调查、实质审查、业务反馈、单独“继续”或混合操作仍走完整入口，不以短路径跳过授权、版本与证据保护。摘要截断/不可用会明确标记；它不是完整事实或更新源。详见[短查询规则](docs/quick-read.md)和[实测记录](../docs/zl-dev/evaluations/2026-10-26-quick-read.md)。


## 证据失效解释（0.23.0）

新验证回执保存有界分项基线；已有证据失效时，短查询和离线报告能说明 HEAD、行为约定或观察文件变化，并给出原关联范围。旧回执缺基线时明确未知，不推断其他任务改了什么。

历史失效不等于当前仍缺验证；已有新覆盖不因旧记录单独重跑。不根据不同路径缩小必要重验，不改变原指纹与接受规则。升级解释不要求重新人工签字。详见[规则与数据流](docs/evidence-freshness.md)和[包含失败的实测记录](../docs/zl-dev/evaluations/2026-10-26-evidence-freshness.md)。

## 受保护记录写入拦截（0.24.0）

插件附带 PreToolUse hook（`hooks/hooks.json` → `scripts/guard.py`）：Write/Edit 直接改 `~/.claude/zl-dev` 下的 task.json、feature.json、report.html、feature.html 及 contexts/executions 记录时拒绝，并提示 locate → 临时完整 JSON → `update --expect-revision` 的正确路径。Bash 按写入目标启发式检查（重定向、tee、cp/mv 目标、sed -i、Python 写打开），读取和插件 CLI 调用放行。它是防误用护栏，不是沙箱：变量拼接路径等写法仍可能绕过，hook 未运行的宿主也不受保护。真实 Claude Code 会话验证 Write 被拒、文件未变。
