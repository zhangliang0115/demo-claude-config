# ZL Dev

描述需求，让 AI 完成理解、设计、开发和验证；简单交流用文字，有实际阅读需要时用固定页面帮助你理解结果和待决事项。

## 人与 AI 如何协作

人给出目标、约束及必要的业务取舍，AI 在授权范围内调查、实施、检查和修复。报告是这些工作的离线说明，帮助人理解结果及作出真正需要的决定；展开证据和复制反馈都在本地完成，不调用业务接口。

“帮我跑验收测试”只委托检查；“按已约定标准替我验收”还委托标准内的结果判断。后者保留 AI 身份、原始委托和适用版本，完成后不要求人重复同范围核验，也不等于取得新的发布权限。没有待决事项时，报告明确说明当前无需人处理。详细边界见[协作模型](docs/collaboration-model.md)。

## 只保留两个命令
```text
/zl-dev:go 在订单列表增加客户筛选，翻页时保留筛选条件。
/zl-dev:status
```

继续反馈也使用 go：
```text
/zl-dev:go 继续，空结果需要给出清空筛选的入口。
```

无需记设计、审查、测试的命令。AI 按当前任务读取必要指引。需求不同于现有任务时建立新任务；不因存在唯一旧任务就把新需求混进去。多个任务需要定位时列标题供选择。

任务可跨会话延续；go 用本会话在当前项目已确认的关联恢复目标，明确新事项或切换优先。status 可临时查看别的任务，不改变原焦点。缺关联时不猜唯一或最近任务；普通问答不写关联。详见[会话关联与接手](docs/session-context.md)。这不隔离共享代码或转移操作权限。

完整入口设计、事项分支、文件加载与原始提示词见 [go 技术方案（HTML）](docs/go-design.html) 或 [Markdown 源文档](docs/go-design.md)。该说明基于 0.16.0 源码快照，并列出尚未实现及文档不一致之处。

## 报告按需生成

普通解释、追问、进度查询、内部步骤和简单阶段结果默认文字交付，不为生成报告新建任务，也不逐动作 render/index。重要决定、实现和真实证据仍及时保存。复杂方案比较、成批验收、正式交接或用户明确索要页面时，才按需生成或复用固定 HTML；阶段结束本身不强制建页。用户只要文字时尊重其要求，旧报告未更新则如实说明时效。

HTML 由本地 Python 模板生成；减少无必要的资料加载、完整 JSON 往返与重复说明才可能降低模型 token。未测量节省比例，不以减成本放宽证据检查。

## 你打开页面应该看到什么

1. 任务名称、用户问题和目标行为。
2. 当前阶段，以及谁现在要做哪件具体的事。
3. 一个完整的操作例子和最多三项前后变化。

补充材料在同一页按标题展开，点击一次即可阅读。没有内容的章节不会出现在菜单里。报告只展示当前阶段；历史阶段保留在任务数据中，不在当前页面展开。

## 同一个功能跨多个项目
```text
/zl-dev:go 管理台需要支持订单取消。
候选项目：/workspace/admin-web、/workspace/order-api。
先查现状和调用关系，整体设计后再分配项目改动。实施可以由一个人或多人承担。
```

AI 按需进入 [跨项目流程](docs/cross-project.md)，共用整体方案和契约，再分别实施、汇总、联调。功能总览仍使用独立的固定模板。

## 存储与边界

版本 0.21.0，Python 3.9+ 标准库。目前安全写入依赖 POSIX `fcntl` 文件锁；Windows 只读路径仅通过模拟缺失 `fcntl` 的测试，尚未真机验证，写入暂不支持。

任务默认存放于 `~/.claude/zl-dev/projects/<项目名>-<路径哈希>/tasks/`，跨项目功能放于归属工作区的 `features/`。原仓库保存业务代码，产出绑定原项目路径。旧任务不自动搬迁。 Claude Code 对项目外产出目录的访问可能需要针对具体任务目录授权；非交互 CLI 的 acceptEdits 不保证允许这些读写或 Bash。权限拒绝时保留原记录并报告未完成内容，不改全局权限、不换路径或工具绕过。

页面是离线快照；反馈填好后直接复制到 AI 会话，需明确回传，不能直接当作批准。模拟案例不代表代码运行成功。已进行隔离项目的真实模型会话评测，仍需在你的实际项目和模型配置下试用；CLI 测试不能替代业务验收。旧版阶段命令已撤下，统一改用 go 描述操作；更新后按客户端提示重载。

## 更新与状态核对

- `status` 使用只读 `locate/status`，不创建目录或重新生成报告。
- 修改既有记录使用 `update` 和 `locate` 返回的 revision 做比较后写入（CAS）；冲突则拒绝覆盖并重新读取合并。更新不会自动渲染。
- 跨项目实施前运行 `preflight` 核对已确认契约、项目版本和切片依赖。这是流程检查，不能拦截任意代码编辑，也不能代替人工确认。
- 快照核对关联任务身份；换绑任务必须重新同步。历史过期证据保留追溯，当前失败、阻塞或未执行证据继续阻止就绪判断。
- 功能总览默认打开当前阶段，可填写并复制本阶段反馈；复制不会修改记录或批准方案。

0.13.0 的内部验证入口可执行项目已有的 unittest 或输出 JUnit 的测试，保留原始结果、解析数量和前后版本。页面区分模型声明、解析回执与无效回执；解析成功不等于业务覆盖、身份认证或人工接受。当前失败及未解决 P0/P1 先交给 AI，展示阶段不能隐藏阻塞。

人工核验页先列环境准备与操作入口，再给结构化步骤。上轮观察和本次草稿分开；AI 测试角色不代表人签字。环境与预期要在运行验证前确定，填写实际观察不使代码证据无故过期。

具体命令见 [入口流程](docs/entry-workflow.md) 与 [跨项目流程](docs/cross-project.md)。

## 场景专用页面
事项类型决定信息结构，当前阶段决定优先内容。需求设计展示用户流程与方案比较；Bug 展示复现与根因证据；生产事件展示影响和处置时间线；运维展示操作序列与恢复。重构、性能、迁移和升级分别使用工程专项结构。它们是独立视图模块，不是同一 Tab 换标题。详见 [场景布局协议](docs/scenario-layouts.md)。

实际报告只展示当前阶段。examples/index.html 仅为插件演示目录，不是实际任务的工作入口。阶段变化先保存事实，按需更新同一 report.html 为新阶段，其他阶段的记录保留在数据中，不拼接展示。

## 实际使用验证范围

后续已完成一次本地双仓库流程演练（模糊需求、设计、接手、开发、浏览器联调、剪贴板反馈返修、运维恢复与状态查询），结果为“流程跑完但未全通过”。发现的问题与证据见 [全流程演练记录](docs/evaluations/2026-10-23-full-flow.md)。真实用户与生产验收仍未完成。

## 只读业务逻辑与数据链路分析（0.18.0）

```text
/zl-dev:go 只读分析订单取消的条件、异常和退款分支，先不修改代码
/zl-dev:go 从页面实付金额追到接口计算和字段来源；范围为当前管理端及 /明确的接口项目路径
```

短问题直接引用源码回答；持续分析使用独立 analysis 记录。跨项目读取无需建立实施分工或确认开发契约。事实、推断、未知和断点分开保存，来源绑定文件、行号与真实哈希；文件变化时要求重新核对，不自动改绑旧结论。可继续追踪的断点交 AI，缺材料只问具体材料，范围外保留边界。

复杂分析需要审阅或明确要求时才生成离线 HTML：业务逻辑页突出条件与结果，数据链路页突出流转与字段映射；没有业务接口请求，也不要求开发、测试或验收签字。分析材料整理完不表示运行正确。详见[分析流程](docs/analysis-workflow.md)及[本轮评测](docs/evaluations/2026-10-26-readonly-analysis.md)。

## 多会话执行工作区（0.19.0）

```text
/zl-dev:go 继续当前任务；先检查是否有其他任务正在修改同一份代码
/zl-dev:status 查看当前任务实际代码目录，以及已登记的并行活动
```

开始实施/验证前按需核对 checkout 并登记活动；同一份代码的两个写入或验证会提示冲突，只读可并行且保留变化风险。不同 worktree 可识别为同一本机 Git 仓库的不同 checkout，但端口、数据库等资源仍需明确核对。已有 write 内执行测试不重复申请 verify。

活动不授予权限、不拦截外部编辑器、不自动建 worktree，也不因超时自动释放。任务原路径和证据绑定保持原样；跨机器逻辑项目迁移、强制接管和证据迁移尚未实现。报告页脚可展开代码位置与代码/行为指纹。详见[执行上下文](docs/execution-context.md)。

## 提示词与续作收敛（0.19.1）

共用规则集中在 entry-workflow.md，go 和内部动作不重复抄录；当前版本已在上下文时不重复加载。schema、团队和阶段模板按实际缺口读取，历史设计快照不作为当前提示词。

仅切换焦点走 resolve/bind 短路径；仅导出已有交接材料走 locate/handoff，离线分析不查端口或启动服务。必要事实与安全校验保留，报告仍按需。

跨项目总览不固定要求人工重验，也不从子任务通过或自由文本推导整体接受；功能级整体验收自动聚合尚未实现。详见[本轮评测](docs/evaluations/2026-10-26-prompt-consolidation.md)。

## 报告复用与模板时效（0.20.0）

事实、评估、模板和实际页面一致时，显式 render 也会复用原文件，保留修改时间和生成时间。展示模板变化会单独提示过期；更新页面不改任务事实、不使业务证据失效，也不重跑测试。旧页没有模板版本时保持 unknown，确需页面时再更新。

任务报告与跨项目总览均适用。status 仍只读，用户仍只用 go/status。详见[报告复用规则](docs/report-reuse.md)；长进程升级后需重载，新旧客户端混用不具备同等保护。

## 成本采样工具与初始基线（0.21.0）

新增维护用离线轨迹分析器及显式成本采样脚本，不新增日常命令、不自动追踪或启动模型。固定旧版与当前版的三组、六次真实会话已留档，模型 usage、缓存、工具输入/返回、文件变化和耗时分开记录；金额未知口径不当账单，字节不换算 token。

本轮是单样本初始基线，ZL-11 仍部分完成。工具调用减少不代表输入 token 全面降低，也未证明应该立即建设通用增量 JSON 引擎。维护者须从有历史提交的源码 Git checkout 准备采样，安装缓存不能直接 prepare；离线分析既有日志可独立使用。详见[采样方式](docs/cost-baseline.md)和[实测结果](docs/evaluations/2026-10-26-cost-baseline.md)。
