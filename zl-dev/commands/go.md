用户输入：$ARGUMENTS

先读 docs/workflow.md（相对于 ${CLAUDE_PLUGIN_ROOT}），但不要把文件格式和阶段操作转交给用户。

1. 从当前项目和会话定位任务；调用 `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/reviewable.py" continue --project <项目真实路径>`。只有一个任务时继续；多个时简短列标题供选择，不默默选最近任务；没有任务时从描述建立最小记录。用户不是来填写 JSON 的。
2. 先查实际代码和项目约定，用一个具体例子解释推荐行为，必要时展示最多三个影响结果的未知项。已明确授权、可逆的工作连续推进，不在每一阶段反复等“继续”。跨项目按 feature 流程整体设计。
3. 最小记录只需目标、范围、行为例子和实际证据；stage_details 按需要补充，不强制填满九个阶段、角色或交接表。单人任务无须自我交接。直接维护 canonical behaviors/scenarios/implementation/evidence，详细阶段仅在有额外信息时填写。
4. 实施一个可运行切片，执行真实检查，发现问题修复后重跑。有界面且浏览器可用时检查实际交互并提供真实截图来源；不可用说明限制。HTML 场景模拟不能替代实际产品演示。
5. 用 render 更新同一页面，返回绝对路径；聊天只给可见变化、真实验证、需要人的决定和下一步。默认首页帮助人理解结果，深层技术细节折叠。不把页面漂亮或字段完整当作完成。

用户反馈是任务输入，读取后继续工作。HTML 草稿导出仍需明确回传并核对版本；不要冒充在线审批。人确认前不宣称验收完成。
