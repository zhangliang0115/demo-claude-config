## 产品约束

- 长期任务可跨会话延续；会话关联、执行工作区、运行证据分别表达。
- 用户仍只需 `go/status`。不增加每轮选任务、填阶段或维护 JSON 的负担。
- 会话关联不转移权限，不是独占锁；不建立全局 `currentTask`。
- 不默认每个会话都建 worktree；不因任务目录不同就声称代码、端口或测试数据已隔离。
- 普通对话、事实持久化和 HTML 交付分开。保留证据检查，不以减少 token 为由放宽当前失败、版本或授权规则。
- 产出策略采用合理默认和自然语言覆盖，不要求用户每轮选择模式；`feature.html` 与任务报告同样按需，不在每个子动作结束时重生总览。

## 报告生成策略的拟定验收表

下表为 0.16.1 已写入入口及动作指引的产出策略；普通对话是否遵循仍取决于 Agent，CLI 的 --no-render 已由回归验证。

| 情况 | 对话回复 | 事实保存 | HTML |
| --- | --- | --- | --- |
| 普通概念解释、已有结论追问 | 直接回答 | 没有新事实则不写 | 不生成 |
| “进展如何”/`status` | 紧凑摘要 | 不写 | 不生成；需要时给已有链接与时效 |
| 内部调查、单个切片的中间进展 | 必要时简短说明 | 重要事实及时保存 | 不因内部动作结束而生成 |
| 新增关键业务决定/委托/验收结果 | 明确记录含义 | 及时保存 | 形成实质审阅/决策材料时生成；零散补充可合并 |
| 完成可供人理解的阶段成果 | 结果、依据、下一步 | 保存 | 按可见变化、复杂度与实际阅读需求生成；简单确认或小修结果可文字交付，不因“阶段完成”强制建页 |
| 人确需比较方案或处理复杂待决事项 | 说明要决定什么 | 保存材料与待决项 | 有助理解时生成，不为每个简单问题强制建页 |
| 换人/换工具正式交接 | 接手范围与入口 | 保存，按需导出交接包 | 生成或复用当前有效报告 |
| 用户明确要求“生成/更新/看报告” | 提供真实链接 | 必要时先核对 | 已当前则复用；已变化则按需生成；无事实不编造 |
| 生产紧急处置 | 优先说明影响及已授权动作 | 保留关键现场与操作证据 | 不让页面制作阻塞处置，稳定后整理 |

HTML 是固定模板由本地 Python 渲染，生成 HTML 文件本身不直接要求模型逐字输出页面。需实测的 token 成本主要来自重复加载指引、读取与重写完整 JSON、重复解释事实及冗长工具返回。减少渲染次数也可减少工具调用和无效操作，但不能据此推算 token 节省比例。

## 验证场景与状态

1. 同项目两会话、不同只读任务：各自继续，互不串任务（ZL-03/04）。
2. 新会话新事项、项目只有一个旧任务：不误复用（ZL-03）。
3. 同会话切换任务后继续；缺失宿主 session ID 时恢复（ZL-04）。
4. 多会话同任务、读同 revision 后竞争写入：不丢更新，不扩大权限（ZL-04/12）。
5. 不同任务同 checkout 写入及测试端口/数据共享：识别实际边界（ZL-08）。
6. 同仓多 worktree、跨机器接手、跨项目总功能与子任务：关联明确、证据不混（ZL-09）。
7. 旧快照晚渲染：当前页面不回退；template 变更可识别（ZL-05/10）。
8. 连续解释、追问、进度和无变化继续：不生成 HTML，不重复装载全部资料（ZL-01/02/06）。
9. 关键决策、阶段成果、交接和显式要求页面：按需产生材料，链接与版本真实（ZL-01/10）。
10. 只读链路分析：不进入实施验收，断点明确（ZL-07）。
11. 当前失败、过期证据、旧页反馈：减成本后仍不会被当成通过或新授权（ZL-02/05/10）。
12. 同组场景优化前后成本对照：实际 usage 与工具工作量分开记录（ZL-11）。
