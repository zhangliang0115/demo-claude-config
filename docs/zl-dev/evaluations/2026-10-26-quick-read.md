# 已有记录短查询评测 · 2026-10-26

## 原因与改动

0.21 初始成本轨迹显示，当前版只看进度仍会读完整入口、列目录、读 task.json，甚至读项目源码；索要已有报告还会读取 HTML 再确认。locate 缺业务目标，使模型为解释目标继续查材料。

本轮在 locate 返回层补 task_brief/feature_brief，不改 snapshot、业务指纹或报告。人类文本每字段最多1200Unicode字符，身份/路径保留完整，截断/不可用/设计目标缺失明确标记；analysis 附问题/结论，feature 标明 goal 来源。预览不是任务更新源，旧字段和版本语义不变。

go/status 的纯已有记录查询先读短协议；单独“继续”、新源码调查、实质审查、业务反馈/决定、生产操作及混合请求仍用完整入口。status 永不 render；go 只有明确索要当前页面时才能按时效生成派生产物，不转成业务写入。当前失败/P0/P1、接受来源和发布边界保留。

## 真实 Claude 验证

控制器创建私有候选插件和四个独立 Git/feature 记录夹具，业务语义与先前基线相同，但本轮是功能验证，不是新旧版本同步随机对照。四个全新真实 Claude Code 会话，用户现有模型设置不改；Read/Bash 工具范围与旧基线包含 Write 的设置不同，不能把 usage 差异归因为插件改动。

四份轨迹解析完整，业务源码、task.json 和 HTML 的前后字节/mtime 均保持。模板过期只由控制器在私有副本 CSS 加注释制造，没有改工作区或已安装素材。最后两份报告保持 stale，未为了得到绿色状态刷新。

混合分析指出夹具没有订单/权限实现，限制为记录层面的规则影响，没有冒充真实代码链路验证。用户明确要求不改记录/源码，实际均保留。按需进入完整流程，不追求所有请求都缩短。

## 剩余问题与收尾

模型仍有冗余：进度查询先 ls，status 重读自己的技能文件，部分答复附带本轮不需要的交接包缺失提示。混合请求先试读短协议才分流完整入口。功能边界正确不等于严格零冗余。

因此进一步强化 go 的“先读完整个请求再决定分支”，并提示 brief 只代表记录，空实施记录不能证明源码未实现；不因一次成功宣称所有模型都遵循。该文案强化在四次调用后完成，没有额外模型补跑，也不把旧调用当成强化后独立复测。

测试时短指引为3,780 UTF-8字节，收尾补事实/授权边界后为3,977字节；完整入口约21KB。这个数字只描述加载材料体积，不换算 token。工具 Read=0 的场景用 Bash cat 读取，绝不解释为没有材料读取或零上下文成本。先前成本基线与本轮条件不同，不给统一节省率。

348 项全量回归通过（97.924s），其中新增6项预览边界测试，既有feature42项定向回归通过；身份/原状态字段、哈希不变、未知/非字符串/截断和副本不可变均覆盖。项目绑定冲突是本轮协议要求，既有 locate 的 --project 不会自动校验绝对目标归属，不宣称新增强制写锁或授权检查。
