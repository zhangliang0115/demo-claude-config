# 提示词收敛评测 · 2026-10-26

## 实现范围

ZL-06 收敛当前入口、13 个内部动作、reviewer、workflow/team/cross-project 和展示协议。入口承担共用规则，内部动作仅补专项要求。当前版本已加载时复用上下文，规则缺失、版本变化或真实矛盾时再读相关文件；不减少项目源码、任务事实、CAS、旧证据或权限核对。

独立审查定位并修复六类矛盾：workflow 强制加载 team/schema/stage 的瀑布；跨项目固定以人工核验收尾；feature 运行时固定催人工；跨机器要求无法执行的路径重绑；离线交接强制查进程/端口；旧工作协议遗漏 analysis 并要求用户最终核验。go 精简后，项目约定、缺陷复现、生产默认只读及具体授权/停止/恢复要求补回入口，避免删掉共用边界。

feature 的机器判断仍只有联调准备度，不新增功能级整体接受汇总、委托模型或发布权限。自由文本、子任务通过与复制反馈不会自动变成整体接受。顺带修复“人工核验”阶段误选项目识别页的问题。历史 go-design 源码附录保留，只增加当前协议提示，不把历史快照改写成新实现。

## 真实模型评测方法

控制器创建隔离 Git 项目、一份两行函数的静态 analysis 记录和真实来源哈希，未运行业务服务或业务测试。两个独立真实 Claude Code 会话通过 --plugin-dir 加载本轮插件，使用用户已有模型配置。流式 JSON 保存实际 Read/Bash 工具调用，区分模型声明与控制器检查；allowedTools 不是硬沙箱，实际行为以原始轨迹和文件核对为依据。此为合成场景，不是真实人工业务反馈。

### 仅关联任务

首次返回 success、6 个原始 num_turns、无 permission_denials，但多做目录列举和 task.json 读取。协议将“信息已明确时不必补查”加强为直接 resolve/bind、无异常不先 ls 或重复读取记录。

同一用户描述用新真实会话复测：success、4 个原始 num_turns、无 permission_denials。实际只 Read 当前入口，然后一次 resolve、一次 bind，返回 bound 后结束。没有继续开发、导出、渲染或扫描插件源码。它证明本场景短路径可执行，不代表所有模型与所有场景有相同轮数或成本。

### 离线分析材料交接

首测返回 error_max_turns（原始 num_turns=15），达到设定轮次上限；没有完成导出。实际读取入口、handoff、任务和源码后，反复查询脚本、schema、目录与 --help。没有启动服务或业务接口，但不能把“未跑偏到业务执行”当作交接成功。

据此把 handoff 动作拆成仅导出短路径和确需更新内容两支：已有目标只用现成 locate → handoff CLI，不先新增 roles/handoffs，不读脚本查命令，不为简单导出强制生成 HTML。真实接收者的 accepted 及实际责任变更仍单独记录，不静默代人确认。

复测返回 success、11 个原始 num_turns、无 permission_denials。实际 locate/handoff 导出成功，没有生成 HTML，没有启动服务或查端口；控制器核对源码和 task.json 字节均未变，HANDOFF.md 为 current。仍发生目录列举和额外文件读取，未完全遵守最短路径，作为模型执行效率限制保留，不把导出成功说成零冗余。

检查真实生成物还发现模板遗留“完成后 render”和无条件核对运行环境，且 analysis 结论未直接显示。该问题属于插件生成内容，不能仅靠动作文档覆盖；本轮同时修正导出模板，增加紧凑分析问题、结论和来源，保留生成区外人工笔记、原版本及历史保护。旧生成物单独归档，不把后来控制器或模型的重导出混成第一次成功。

模板修复后 resume 真实 Claude 会话，返回 success、6 个原始 num_turns、无 permission_denials。实际重新读取 handoff 动作，调用 locate/handoff 后读取生成物并额外检查目录/文件信息；仍非零冗余，不宣称严格只调用两次。独立检查确认新版问题、结论、来源行号已带入，未出现过时的待明确阶段；HANDOFF 为 current，源码和 task.json 字节保持，未生成报告。此步骤的输入明确要求重读新版模板，不冒称无提示的自主发现。
