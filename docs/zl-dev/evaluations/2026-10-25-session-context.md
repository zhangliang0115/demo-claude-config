# 会话关联验证（0.17.0）

## 范围

保留长期 task/feature，在独立索引中保存宿主、会话 ID 与项目/工作区作用范围下的当前焦点。新增内部 session_context.py 的 resolve/bind/clear；用户入口仍为 go/status。关联只用于定位，不是身份认证、权限、代码锁或运行环境隔离。

缺失、损坏、目标失效或无可靠 ID 时不猜唯一/最近任务。明确任务和切换优先；status 临时查询 B 不改原焦点 A；子代理不修改父会话关联。CAS 失败保留旧焦点并明确未切换，不能把新工作落到旧任务。纯关联请求使用短路径，不执行开发、业务验证或生成 HTML。

## 回归与审查

新增 20 项专项测试覆盖两个会话两个任务、同会话切换、同任务多会话、项目/宿主作用范围、feature、损坏索引与失效目标、读路径无写、CAS/幂等/清除及历史边界。全量 214 项通过（30.888 秒）；独立审查再次运行 20 项通过。

审查发现并修复目标身份竞态：首次核对任务 A 后，持锁重读若同路径已变为任务 B，现在拒绝绑定，不静默选择替代目标。损坏索引的显式 CAS 修复会保留原字节备份。

marketplace 与 plugin manifest 的严格校验通过；这不是官方目录上架认证。

## 真实 Claude Code 验证

客户端 2.1.310，模型沿用用户原配置 opendesign/deepseek-v4.1-flash[1m]。控制器创建临时 Git 工作区及两个合成任务；真实 Claude Code 负责关联和恢复，没有实现业务网站或发业务接口请求。

1. 两个不同 UUID 的真实客户端会话分别调用 go 关联任务 A/B。技能中展开的 ID 与客户端结果中的 session_id 一致。
2. 分别通过 --resume 恢复并执行无目标 status，均返回各自任务标题，任务事实未改变、HTML 未生成。
3. 首次 A 绑定触及 max_turns=10 限制（11轮、无最终答复）；索引已保存，随后恢复成功。B 首次9轮成功。原始失败和成功记录都保留，不视为连续无中断通过。
4. 根据实测绕路，补充纯关联/切换短路径，避免扫描插件目录、读源码重算、重复查询或执行 continue。
5. 同两会话相互切换目标后复验：A/B 分别4轮、5轮成功，随后各自无目标 status 返回切换后的目标。
6. A 显式查询另一任务，返回指定标题且原焦点保留。两份 task.json 的 SHA256 均与控制器初始化后相同，整个过程没有 report.html。

这些是当前配置下的少量流程样本，不证明所有模型会严格遵循提示词，不是模型优劣或 token 节省率基准。用户的真实业务任务未修改。

## 保留边界

- 默认加载和调用仍由 Agent 遵循技能指令；内部工具保证其实际调用的校验与关联行为。
- 新事项创建/关联失败会保留旧焦点，需明确说明未切换；未新增 pending-intent 事务状态。
- 本轮不改变物理路径形成的项目桶，不搬迁旧任务、不自动迁移关联或权限。
- 多任务共享 checkout、端口、数据和测试进程的干扰，以及旧报告快照晚写覆盖，仍为后续 TODO。
- 旧 CLI 的无目标单候选选择保留兼容；go/status 新流程不使用它作为会话身份依据。
