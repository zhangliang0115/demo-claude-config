# 第二轮实测：名额调整与候补晋升

本轮从 2026-10-23 持续到 2026-10-24，换成已有业务规则调整，使用两个独立 Git 仓库、真实 HTTP 服务、SQLite 和浏览器。通过 Claude Code 实际调用插件，经历模糊需求、规则确认、API 开发、中途变更、全新会话接手管理台、报告反馈返修。不是只换 task.json 的演示数据。

测试插件是持续修复中的 0.12.0 开发版，不是从头到尾冻结的同一个发布包。运行器为 Claude Code 2.1.309，实际模型沿用本机的 `opendesign/deepseek-v4.1-flash[1m]`。没有验证不同模型之间的稳定性；控制器扮演需求与验收角色，不能当作真实业务人员签字。

## 场景与执行

基线活动有 2 个名额，alice/bob 已报名，carol/dave 按顺序候补。API 原来只支持报名与查看，管理页只读。目标是运营调整名额，并按先后顺序自动晋升候补。

| 步骤 | 输入与实际检查 | 结果 |
| --- | --- | --- |
| 模糊需求 | 先读两项目和实时接口，集中提出缩容、顺序、关闭活动、审计、通知等问题 | proposed v1 的 preflight 返回 2，未写业务代码 |
| 规则确认 | 缩容不踢人、FIFO、非 open 禁止、审计同事务、稳定请求键与版本冲突 | 保存 v2 契约及两个任务绑定后 preflight 返回 0，随后才编辑 API；15 项实现者测试通过 |
| 独立 API 检查 | 参数边界、幂等、并发、事务提交、审计失败注入 | 首次 32/33 通过：审计失败虽回滚，却直接断开 HTTP 连接 |
| 中途规则变更 | 单次最多扩容 3 人；通过真实功能页填写并原生复制反馈 | 先升 v3 并通过 preflight，再实现 +3/+4 边界和结构化 500；17 项实现者测试、35 项独立 HTTP/SQLite 检查通过 |
| 全新会话接手 | 特意交付旧 v2 HANDOFF，要求核对总方案、代码与实时服务 | 识别 v2/v3 差异，并纠正“本轮只做 API”被写成整体目标、旧项目观察和旧角色描述；管理台首版 50 项浏览器断言通过 |
| 独立浏览器复查 | 实际控件输入与点击；版本冲突；响应丢失后他人修改，再重放旧请求且刷新失败 | 找到遗漏：数据库为 5/v4，页面却把历史结果 4/v3 标为“当前”，仍允许修改 |
| 报告反馈返修 | 在真实 admin report.html 填写不符合预期及原因，点击复制，核对系统剪贴板内容，再回传原会话 | 返修与最终复测结果见下方最终记录 |
| 证据复核 | 测试后验收约定变化，却把旧证据改绑新指纹 | 恢复运行时绑定，冻结最终约定重新测试；新增 update 校验拒绝直接改绑已有证据 |

v3 API 的独立 35 项检查还包含：16 个同键并发请求只写一条审计、两个运营同版本竞争只能一方成功、报名与扩容并发保持已有候补优先、HTTP 成功必须在事务持久提交后返回。数据与服务均为本地测试对象，身份头是测试注入，不是生产认证。

v3 修复调用曾因控制器设置的预算上限中断：代码与测试已完成，但最后同步未执行。保留该次错误结果，另一次恢复调用完成同步；没有把中断记为成功。

## 插件修复

- `status` 改用只读 `locate/status`，查询不再调用会渲染页面的 `continue`。
- 提供任务和功能的 `locate/update`：校验绑定、比较原始记录 revision、协作锁与原子替换；更新与渲染分开。并发冲突拒绝覆盖，权限错误原样失败，不提供绕过权限的路径。
- 跨项目实施前增加只读 `preflight`。本案例的 v2、v3 与新会话实施都留下了“核对成功先于业务源码编辑”的会话证据。它是流程约束，不是任意 Edit 的技术拦截。
- 功能页按当前阶段默认展开，读取真实设计目标，支持本阶段填写并复制反馈；复制本身不批准或修改记录。
- 历史过期证据保留追溯，当前失败/阻塞/未执行继续阻止就绪；同一当前版本的失败不能被另一条通过掩盖。
- 快照绑定规范任务路径和任务 ID，换任务后旧快照必须过期，不能继续用旧验证结果。
- 将 `fcntl` 延迟到写锁操作，缺失时只读路径不因导入失败而崩溃，写操作明确失败且不写文件。Windows 只模拟模块缺失，未真机验证。
- 验证指引补充按风险选择组合故障，核对数据库、页面表达与真实控件；交接先复述整体目标、本轮范围和版本差异，核查实时进程。
- 已绑定证据必须保留原 ID，不能直接改绑另一非空 revision；重跑新增记录。允许显式清空失效，不能借清空再重绑。这个保护不能证明测试真实执行，也不能阻止恶意伪造新的记录。
- HANDOFF 导出记录精确任务 revision 与代码/行为指纹；locate/status 只读区分 current、stale、unknown、missing。旧格式标为 unknown，不把旧包默认当成当前。不会自动覆盖接手包中的手工补充；核对后显式导出。
- 功能页顶部行动提示跟随阶段；人工核验阶段不再要求“先识别项目、分配开发”。

## 边界与保留证据

接手会话确实在编辑前读取了契约并通过 preflight，但完整的接手差异复述主要出现在最终回复；“先显式复述再实施”的顺序仍依赖模型遵循。新指引已补充，不能把文档修改当作该顺序在新一轮运行中已被证明。

本次未涉及生产部署、真实运营签字、多实例数据库、真实鉴权、多活动、跨模型或跨 Agent 工具。任务中的人工核验保持 pending。自动化通过只说明这些用例在当前环境通过，不代表插件已能保证任意任务正确。
