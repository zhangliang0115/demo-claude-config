# ZL Dev 真实项目试用指南（M6）

M6 需要真实使用者，AI 不能代替。本页让试用可以直接开始，并让反馈能和插件版本、任务记录对上。

## 选项目

选 1～2 个正在进行的真实项目，最好覆盖两类：

- 一个需求或缺陷修复：会经过理解 → 实施 → 验证。
- 一个只读分析或交接：让另一个人或另一个工具接手。

不要选生产紧急事件做第一次试用。

## 怎么用

```text
/plugin marketplace update zl-dev-marketplace
/plugin install zl-dev@zl-dev-marketplace
/zl-dev:go <用平常的话描述需求>
/zl-dev:status
```

照常工作，不需要为试用改变习惯。

## 每次试用后记录

在仓库开 issue，标题 `trial: <项目类型> <日期>`，内容按下面填，不知道的写“不知道”：

| 项 | 填写 |
| --- | --- |
| 插件版本 | `/plugin` 里看到的版本 |
| 模型 | 例如 claude-sonnet-5-5 |
| 任务类型 | 需求 / 缺陷 / 分析 / 交接 / 运维 |
| 是否完成 | 完成 / 部分 / 放弃 |
| 最有用的一点 | |
| 最想改的一点 | |
| AI 是否做了你没要求的事 | 有的话写具体内容 |
| AI 是否声称完成但实际没做 | 有的话写具体内容 |
| 报告页是否看过、是否有用 | |
| 任务目录 | locate 返回的 task_dir（不要贴 task.json 原文） |

## 我们会怎么用这些反馈

- 同一问题出现两次以上，进入 TODO 并写验收条件。
- 涉及“声称完成但没做”“越权操作”的，优先处理。
- 试用记录放在 `docs/zl-dev/evaluations/`，标明“真实使用反馈”，与合成评测分开。
