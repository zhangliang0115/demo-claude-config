本轮变更及取舍见 [方案修订记录](./MemHub-方案修订记录.md)；工程任务见 [实施计划](./docs/superpowers/plans/2026-10-18-project-memory-v1.md)。研发和签收以本方案、验收标准及其同版本实施计划共同为准；调研报告保留为历史背景。确认研发方案不等于授权读取真实会话、外发数据或安装宿主接入。

## 1. 推荐决策与成功标准

**自研一个轻量的 Claude Code 项目记忆助手：从授权项目的会话中提取长期约束、约定和决定，经用户审阅后，在后续会话中自动提示。** 不以安装 MemHub 为实施主线，也不依赖其 SDK 的数据模型。

首版只回答一个问题：用户昨天明确说过的项目约束，今天开新会话时，能否被准确、及时地带回来，而且能查来源、修改和撤回？

采用以下默认边界推进，无须先补齐所有未来产品需求：

| 项目 | v1 决策 |
|---|---|
| 使用者 | 单机、单用户；首轮试点仅启用一个明确授权的项目；一个 dataDir 只登记一个项目，另一项目须用独立目录 |
| 宿主与平台 | Claude Code；先验收 macOS，其他平台后续评估 |
| 记忆类型 | `constraint`、`convention`、`decision`；个人偏好、代码发现和修复经验留到 v1.1 |
| 数据输入 | 本地 transcript 文件；文件监听加定期补扫，不安装采集 Hook |
| 生效方式 | 自动提取候选，显式交互审阅后生效；内置模型/后台管线没有批准或停用旧规则的权限；交互确认不是可信真人认证 |
| 召回方式 | 仅已批准、有效且明确为全项目范围的规则进入启动注入；局部路径规则通过 CLI 带范围查询；范围未知不可批准 |
| 数据与模型 | 存储在本机；抽取调用用户显式配置的免费 OpenAI 兼容 API；除该端点外不发起网络请求，不启用遥测 |
| 实现 | TypeScript + Node.js 24 LTS + SQLite；CLI 先行，随后提供极简本地审阅页 |
| 周期 | 旧版 25–30 人日仅保留为初始估算；G0 后重估；G1-V 收益门通过后再投入 Web 等扩展，不承诺六周完成 |

**数据边界必须说清楚：** v1 采用免费 API 平台后，**会话内容会发送给该第三方服务做抽取，不再承诺“数据不出本机”**。本助手只保证：存储在本机、只访问用户显式配置的单一端点、发送前脱敏与最小化、发送内容可预览、密钥不进入日志和导出。免费平台的服务条款、数据保留与训练政策、速率限制和可用性必须在 T01 由用户确认；条款不接受的平台不采用。Claude Code 自身的云端流量属于宿主行为，另行计算。

交付成功必须同时满足：

1. 会话 A 中明确的长期约束，经确认后可在会话 B 自动出现，并影响可观察的任务结果。
2. 用户能看到每条记忆的脱敏支持证据；未批准、已拒绝、已撤回和人工确认未解决冲突中的条目不会作为确定事实注入。模型提出的疑似冲突仅告警，不改变原已批准状态。
3. 重扫、重启、文件截断、模型失败不会造成重复记忆、无声丢记录或撤回条目复活。
4. 助手停止或发生故障时，Claude Code 能继续正常使用。
5. 抽取只访问用户配置的免费 API 端点；断网时导入、审阅、检索和注入生成仍可用，抽取进入可恢复的阻塞状态，不丢失未处理数据。
6. 发送给第三方模型的内容经过脱敏与最小化，用户可在配置后预览实际请求；密钥不出现在日志、导出和错误信息中。

## 2. 对原草案的必要修正

以下取舍直接决定实现是否闭合。报告中的竞品热度、产品版本及性能宣称不作为本方案的验收证据。

| 原草案问题 | 本方案修正 | 理由 |
|---|---|---|
| “全离线”同时提供远程模型 | 明确使用免费 API 平台，并限定单一配置端点、发送前脱敏、可预览请求 | 免费可用优先于离线承诺；不把“本地存储”说成“数据不出本机” |
| 只凭正文哈希生成消息 ID | 优先使用宿主消息 ID 与内容块序号，正文哈希仅检测变化 | 同一会话的两次“继续”是两个事件 |
| 文件 inode/大小判断重写 | 增加游标附近内容锚点及文件代次 | 同 inode、同大小的覆盖也会发生 |
| 一条 JSONL 记录等于一条消息 | 按 content block 拆分，并记录记录级处理结果 | 文本、工具调用、工具结果可能混合 |
| 文件无变化或 Stop 等于会话结束 | 空闲仅触发 flush；不宣称会话已结束 | 工具可能仍在运行，会话可能恢复 |
| 两阶段审查只看候选和旧记忆 | 审查必须同时读取原始证据片段和作者信息 | 引用 ID 存在不能证明候选真实 |
| 约束也只给标题 | 约束和约定给完整短句，决定等给索引 | 降低模型忘记进一步查询的概率 |
| SQLite 与可编辑 Markdown 都可写 | SQLite 是唯一权威源，Markdown 只作导出 | 避免双写、冲突和绕过审阅 |
| `merge` 原地覆盖内容 | 内容修订创建新 revision，保留旧版和审计事件 | 允许追溯与回退 |
| 删除后只清理关联表 | 增加撤回状态、抑制规则与恢复检查 | 防止重新扫描后再次抽出 |
| 用消息数等于文件行数验收 | 按“输入记录均有处理结果”验收 | 一行可拆出多条消息，也可合法跳过 |
| 默认 FTS5 + 向量一起做 | 先验证 FTS5 中文检索，向量由失败样本驱动 | 首版少量明确约束不必依赖语义模型 |
| 许诺固定注入位置、替换旧 Block | 只承诺宿主文档和实测支持的行为 | Hook 无法被假定拥有任意上下文编辑能力 |

## 3. 用户操作闭环

以下是产品必须实现的操作顺序，命令名暂定 `mem`，发布前检查是否与用户已有命令冲突。

| 步骤 | 操作示例 | 用户得到的结果 |
|---|---|---|
| 1. 检查环境 | `mem doctor` | Node、SQLite/FTS5、模型端点、目录权限和宿主兼容性结果 |
| 2. 登记项目 | `mem init --project /absolute/project/path` | 注册项目，显示数据目录及将读取的来源；此时不启用 Hook |
| 3. 预览输入 | `mem import --dry-run` | 会话数量、大小、可解析比例、预计批次数；不调用模型 |
| 4. 导入样本 | `mem import --since 7d` | 在授权范围内导入最近七天样本，输出处理账本 |
| 5. 提取候选 | `mem extract --pending` | 两阶段抽取完成，结果均处于待审阅状态 |
| 6. 审阅 | `mem review` | 逐条看证据、批准、拒绝、修改或裁决冲突；MVP 是 CLI，v1 增加 Web |
| 7. 预览注入 | `mem context --preview` | 与 Hook 相同的记忆块、版本和预算统计，不改宿主配置 |
| 8. 接入宿主 | `mem install --host claude-code --dry-run`，随后显式执行安装 | 预览并合并一个项目级注入 Hook，保留其他设置 |
| 9. 持续运行 | `mem serve` | 启动单个 Core，监听与补扫授权来源，后台提取候选 |
| 10. 检索与治理 | `mem search "数据库命名"`、`mem show <id>`、`mem revoke <id>` | 查来源、查看当前 revision、撤回生效记忆 |

安装是用户主动执行的产品操作。本次仅编写方案，不安装助手、不读取真实会话、不改动 Claude Code 设置。

默认先以人工启动的 `mem serve` 试点。需要开机运行时，v1 最后阶段再通过显式安装命令登记 macOS LaunchAgent；卸载只移除自身服务与配置项，默认保留用户数据。

## 4. 系统分工与目录

处理顺序：授权目录 → 文件读取 → 分块规范化与隐私过滤 → SQLite 证据 → 完整 turn 缓冲 → 候选生成 → 证据审查 → 用户批准 → 生成召回结果。

| 模块 | 负责 | 不负责 |
|---|---|---|
| Source adapter | transcript 定位、版本探测、记录/内容块解析 | 判断哪些记忆该生效 |
| Reader | 增量读、半行处理、重写检测、输入账本 | 直接调用模型 |
| Core | 所有业务写入、项目校验、队列、版本事务 | 执行会话文本中的命令 |
| Extractor | 已配置远程模型调用、结构校验、证据核验、候选裁决 | 绕过用户批准写 active |
| Recall | 查询有效版本、中文检索、预算打包 | 调生成模型重写 query |
| CLI / Web | 审阅、查询、诊断、导出 | 持有独立记忆副本 |
| Hook adapter | 验证项目、读取最新已批准内容、返回上下文 | 扫描文件、抽取、加载本地 LLM |

每个 dataDir 的 Core 是单一写入者。CLI 通过本机 IPC 提交变更；需要离线导入时可启动短生命周期 Core，并争用同一实例锁。Hook 使用短时只读 SQLite 连接，不依赖常驻服务在线，不自行创建或迁移数据库。

项目目录建议：

```text
project-memory/
  src/
    cli/             # 命令、输出与退出码
    core/            # 项目登记、授权、单写者与生命周期
    sources/claude/   # 版本探测和解析纯函数
    ingest/          # 游标、账本、turn、批次
    extraction/      # 模型适配、schema、两阶段裁决
    storage/         # migrations、事务、关联表
    recall/          # 搜索、索引、上下文预算
    governance/      # 审阅、修订、撤回、抑制
    integration/     # Hook 与宿主配置安装/卸载
    review/          # 本地审阅界面
  prompts/           # 有版本号的生成/审查提示词
  tests/fixtures/    # 合成或经脱敏授权的 transcript
  evals/             # 标签、评测配置及结果
  docs/              # ADR、安装、隐私、恢复与兼容矩阵
```

运行数据默认置于 `~/.project-memory/`：`memory.sqlite`、无正文日志、实例锁和安装清单。目录仅当前 OS 用户可读写；不存入项目 Git 仓库。具体配置 schema 在 T01 冻结。首版备份仅写入该 dataDir 的 `backups/` 受管子目录，manifest 必须绑定唯一 project ID；不支持跨项目共享快照、任意外部备份目录或跨项目恢复。对照/隔离测试中的项目 B 使用另一个 dataDir，不改变 A 的授权边界。

## 5. 技术选型与开工验证

| 组件 | 选择 | 开工验证 |
|---|---|---|
| 运行时 | Node.js 24 LTS、TypeScript | 锁定补丁版本；验证目标 Mac 的原生 SQLite 绑定 |
| SQLite 访问 | 优先 `better-sqlite3`，繁重写入放 Core 专用线程 | 若兼容失败再比较 Node 内置 SQLite；T01 只保留一种实现 |
| 数据库 | SQLite WAL + 外键 + schema migration | 并发只读、崩溃恢复、事务回滚、备份恢复 |
| 全文检索 | FTS5 trigram，短词使用受限子串查询 | 中文、英文标识符、路径、两字词及特殊字符 |
| CLI / 校验 | `commander`、Zod | 从 npm 与官方文档核实兼容版本，提交 lockfile |
| 抽取模型 | 用户显式配置的免费 OpenAI 兼容 API（base URL、模型名、密钥） | T01 选定具体平台与模型，记录服务条款、数据保留/训练政策、速率限制、上下文上限和实际质量；免费额度耗尽时显式阻塞 |
| 文件通知 | Node `fs.watch`，30 秒补扫兜底 | 目标 macOS 下验证递归通知、删除、移动、休眠恢复 |
| 测试 | Vitest；Web 验收使用 Playwright | 单元、SQLite 集成、CLI 和浏览器端到端测试 |
| 审阅页面 | 本机 HTTP + 小型页面；单页列表、详情、操作 | 不引入完整管理后台或额外前端状态框架 |

模型不在方案阶段硬编码。T01 必须选定一个通过样例测试的免费平台与模型 ID，之后固定用于开发评测；免费额度、限流、服务条款或模型下线变化时，重新验证而不是静默换模型。模型不可用时保留导入、人工维护和检索能力，抽取标记 `blocked / model_unavailable`。

模型 adapter 只允许访问配置中的端点，禁止重定向到其他主机，禁用代理环境变量继承；配置变更需要用户显式确认并显示端点主机名。发送前执行脱敏与最小化，提供 `mem context --show-request` 预览实际将发送的字段；不发送完整原始 transcript。免费平台通常可用性有限，队列必须按 429/5xx 和配额耗尽分别处理。

开发前执行一次复用检查：用 `gh search repos` / `gh search code` 查找 transcript parser、宿主 Hook 和 SQLite 队列的现有实现，核对许可证与依赖；再核对 npm 注册表和官方 API。只复用稳定小组件，不 fork 整个记忆平台。将查证结果、候选版本及采用理由写入 `docs/adr/001-stack.md`。本次方案交付不等于已完成依赖安装或兼容验证。

## 6. 数据契约与一致性

不直接复制报告的示意 DDL。先冻结下列逻辑表及不变量，再编写带迁移测试的 SQL。

| 表 | 最小字段 / 唯一键 | 作用 |
|---|---|---|
| `projects` | `id`、规范化根路径、授权状态、`authorizationEpoch`、`memoryGeneration` | 授权变更与有效记忆集合分别计版本，避免无关审批导致重新抽取 |
| `source_files` | `project_id`、来源路径、文件标识、`generation`、已提交 offset、锚点 | 文件增量读取与重写检测 |
| `ingest_records` | 文件代次 + byte_start 唯一；结果码、源记录 ID、哈希 | 每条输入记录都可追踪其处理结果 |
| `episodes` | 来源 + 宿主 session ID + 主/子代理身份唯一 | 会话归属，不依赖目录名猜项目 |
| `messages` | 事件 ID、episode、源记录 ID、block index、作者、脱敏文本、哈希、时间 | 不可变证据；新版本追加 |
| `turns` | episode、开始序号、结束序号、状态、revision | 组装完整用户轮次及恢复后的新修订 |
| `jobs` | 类型、输入集合哈希、pipeline version 唯一；状态、attempt、lease、原因码 | 持久队列和幂等处理 |
| `candidates` | job、类型、文本、证据引用、裁决、原因、提议目标 revision | 保存待审阅结果，便于评测 |
| `memories` | 稳定 ID、project、当前 revision 指针、治理状态、`governanceVersion` | 逻辑记忆身份 |
| `memory_revisions` | memory ID + revision 唯一；内容、kind、scope、有效区间、内容哈希 | 内容演化历史 |
| `memory_evidence` | revision ID + message ID + 引用区间唯一 | 强关联溯源，不用 JSON 数组替代外键 |
| `review_events` | 操作、目标 revision、入口、`operator_attested`、原因、时间 | 审阅动作可追溯，但不伪称已验证真人身份 |
| `conflicts` | 项目、关联 revisions、`suspected / confirmed_unresolved / resolved / dismissed` | 模型只写 suspected；暂停规则需显式交互确认 |
| `runtime_state` | `runtimeEpoch`、采集/抽取/注入开关 | 恢复或清空使旧在途提交失效；不依赖独立审计日志回放 |
| `suppressions` | 项目、证据事件/版本、候选 fingerprint、抑制范围 | 防止拒绝/撤回被批量重抽绕过 |
| `active_search` 与 FTS 表 | 当前可用 revision 的整数 rowid、内容 | 可重建的检索投影，不是权威数据 |

关键约束：

- `kind` 在 v1 仅允许三类；所有关系必须属于同一登记项目。适用范围是判别联合：`{type:"project"}`、`{type:"paths",paths:string[]}`、`{type:"unknown"}`，不得用空数组表示全项目。paths 必须为非空的规范化项目内相对文件/目录路径，不支持 glob、越界或符号链接逃逸。unknown 不可批准；project 必须有明确全项目证据或审阅者的显式澄清。
- 审阅时补充范围作为新的 `user_clarification` 记录，保留原证据与修改前候选，不能声称范围来自原 transcript。已批准 paths 规则仅通过 CLI 查询并始终显示路径条件，首版不加入 SessionStart；unknown 仅在审阅视图展示。
- 作者至少区分 `person / agent / tool / host / unknown`；角色与作者独立。
- 模型的 confidence 只作为审阅辅助，不作为正确率，也不决定自动批准。
- 内容修改永远创建新 revision。数据库允许更新当前指针、队列租约等运行状态，但不原地改写历史证据和历史正文。
- `valid_from` 表示明确的事实生效时间，未知时允许为空并说明未知；`valid_until` 为明确结束时间，未知为 null；`created_at` 表示系统录入时间。不得把抽取时间伪装成事实发生时间；明确未来生效或已到期的条目不作为当前有效规则召回。
- 外键开启；来源与项目校验在 Core 入口和查询时执行。客户端传来的 project ID 不能替代校验。

三个必须原子化的事务：

1. **采集事务**：写记录处理账本、消息和来源关联，最后推进文件 offset。崩溃时全部回滚，重启可以安全重读。
2. **任务提交事务**：复核输入证据/turn 版本、authorizationEpoch、runtimeEpoch 和被比对的 memory revision/governanceVersion；Stage B 还校验 memoryGeneration，写候选、关联与任务完成状态。撤权、证据删除或恢复使旧结果失效。只变更有效记忆集合时，保留仍有效的 Stage A 结果，仅在预算内重做 Stage B；预算耗尽转 blocked，不无限重跑。
3. **批准/撤回事务**：写审计事件、更新有效 revision/治理状态、更新检索投影及 FTS，递增目标 governanceVersion，并在有效集合变化时递增 memoryGeneration；普通审批不改变 authorizationEpoch。事务成功后的新查询必须看见新状态。

## 7. 采集：先保证不丢、不串、不重复

### 7.1 来源与项目识别

只读取登记项目对应的 transcript。使用记录里的 cwd/工作目录元信息与本地注册路径匹配，不把 `~/.claude/projects` 的目录编码直接当作仓库唯一 ID。

对路径执行规范化、授权根校验和符号链接边界检查。来源无法可靠归属时进入隔离清单，供用户处理，不自动并入当前项目。首版 worktree、项目移动和多仓库会话不自动合并；需要重新登记或人工确认映射。

### 7.2 文件读取

- 启动补扫 + 文件事件唤醒 + 每 30 秒补扫，合并同一文件的重复通知。
- 初始每文件每轮读取预算 4 MiB，完整单记录上限 8 MiB；大文件分轮处理，不因总大小超过 32 MiB 永久拒绝导入。
- 没有换行符的末尾半条记录保留到下一次，不报永久解析失败，也不推进已提交 offset。
- 单条超限记录流式跳到换行边界，记录 `record_too_large` 和字节区间，不把整条装入内存。
- 文件变小、身份变化或游标锚点不匹配时创建新文件 generation，回到开头按事件 ID 去重。增加定期分块指纹核查，检测仅修改已读取前缀而未触及锚点的覆盖。
- 无法确定是旧事件还是新事件时进入隔离状态，避免把不同事件误合并或把重放记成新事实。

### 7.3 消息身份与内容解析

主路径身份：`source + session_id + subagent_id + source_message_id + block_index`。同身份正文变了则追加证据版本，旧版本的派生条目标记待复核。

缺宿主 ID 时，使用文件代次、byte_start、block_index 作为导入身份；重写后只能在顺序和邻近锚点均一致时关联旧事件。纯正文相同不足以去重。

混合 content 按块处理：用户文本归 person，`tool_result` 归 tool，assistant 文本归 agent，宿主插入归 host；无法确认归 unknown。v1 默认跳过子代理轨迹并记录原因，测试确保其不会进入主会话。后续启用时必须使用独立 episode。

### 7.4 隐私与污染防护

先处理 `<private>`、凭据模式和宿主包装，再持久化可展示文本；被排除片段不进入证据正文、提示词、日志或导出。助手不复制一份未经处理的完整原始 transcript。

脱敏版本保留来源记录引用和指纹，称为“本地脱敏证据”，不声称是原文的完整字节备份。宿主原文件仍由 Claude Code 管理。v1 不做通用工具 payload 归档。

结构化识别来源优先于正则删标签。用户引用的 README、粘贴文档或代码块不能仅因为处在 user 角色就自动视为用户长期指令；标为引用/不确定，不自动生成可批准约束。模型审查和人工审阅是补充防线，标签本身不是安全隔离。

注入内容携带项目、generation 和条目 ID 标记；解析器排除受管注入块及其已知来源，防止“召回→总结→再次抽取”的循环。Agent 转述本身也不能成为用户约束的证据。

### 7.5 Turn 与 flush

一个 turn 从可见 person 消息开始，包含后续 agent/tool 消息。只有工具调用、没有终结回答的 turn 不算已完成；未回答提问保留为 open。

“轮次边界已关闭”和“该 turn 允许抽取”是两个独立判断，不能合并成一个 `closed` 状态：

- 下一条真实用户消息出现时，上一轮边界关闭；但若上一轮没有回答或只有工具调用，它标记为 `unanswered`，**不进入抽取批次**。
- 明确的终结回答元信息存在时，该 turn 才标记 `complete`，可进入抽取。
- 中断恢复、迟到工具结果会产生新的 turn revision；已排队但尚未提交的旧输入由新 revision 替代，已经提交的不回滚，而是在后续批次中作为补充证据处理。
- 实现和测试共用这张判定表；AC-12 按“边界状态 / 完成状态 / 是否可抽取”三列验收，不再用单一 closed 含义。

满足任一条件可 flush：累计 5 个完整 turn、完整 turn 已等待 5 分钟、用户执行 `mem flush`。单批最多 20 个 turn，同时受模型输入预算约束；超过上下文时按完整 turn 分批，单 turn 过大则拆证据窗口并记录覆盖范围，不能悄悄丢尾部。初版超大且不能安全切分的 turn 转入人工处理。

文件空闲不写 `ended_at`，Stop 也不当作 transcript 中必然存在的记录。

## 8. 抽取、审查与治理

### 8.1 Stage A：候选生成

输入为一个冻结批次、作者/引用标签及必要的相邻上下文。生成最多 10 个候选，允许空数组。输出字段至少包括 kind、短标题、自包含正文、证据事件与 revision、逐字引文及偏移、有效范围、理由和不确定项。

仅接受明确长期约束、约定，以及用户已经确认的决定。排除一次性指令、推测、尚未答复的问题、未确认的 Agent 建议和外部资料中的命令。候选不得编造用户未陈述的适用范围。

程序校验必须覆盖：JSON schema、枚举、长度、证据属于当前授权批次、引用区间存在、引文一致、作者类型符合规则。格式不合格不进入治理库。

### 8.2 Stage B：证据审查与去重

输入为候选、对应脱敏证据片段、相关前后文，以及当前项目的已有记忆。不能只给候选和旧记忆。

首版只在已验证的小规模范围内对全部有效记忆按 token 预算分片比对，并汇总裁决。`maxAutoReviewMemories` 初始值为 50；超出该规模时整批自动抽取进入 `blocked / memory_scale_limit`，保留未处理位置，人工审阅/录入、搜索和已有规则注入仍可用。该值限制自动比对规模，不截取前 50 条，也不禁止人工维护更多记忆。

T01 在 50/200/1,000 条历史规模测同一工作负载，记录 A/B 请求数、输入/输出 token、分片、修复/重试、总等待，决定是否调整规模上限。对超过当前上限的规模仅在隔离探针中显式运行；生产不得绕过上限。平台未授权或额度不足时该规模实验记 BLOCKED，不据此提高支持上限。1,000 条本地搜索性能通过不代表免费 API 支持 1,000 条全量审查。后续采用检索预筛选须另立决策并验证冲突召回率。

允许的裁决：

| 裁决 | 条件 | 落库行为 |
|---|---|---|
| `add` | 新信息、证据支持 | 创建待批准的新候选 |
| `merge` | 同一含义，可补证据或改善表达 | 提出新 revision，原 active 版在批准前不变 |
| `supersede` | 明确取代旧约束，范围与时间一致 | 提出替代关系，批准时原子切换 |
| `conflict` | 疑似同范围矛盾，模型无法可靠判断 | 仅创建 suspected 关系和待审提示；原已批准条目的状态/注入不变 |
| `discard` | 无长期价值、重复或证据不足 | 保存短原因码，候选不生效 |

模型不得通过“冲突”变相停用旧规则。审阅者可显式确认冲突为 `confirmed_unresolved`，此时才将相关旧条目置为 needs_review 并暂停注入，或直接裁决保留/替代。证据失效、项目撤权和事实有效期结束仍由程序立即停用，不受此规则限制。审阅列表与 doctor 分别显示 suspected 数、confirmed_unresolved 数及持续时间；疑似冲突积压不得静默消失。代价是新改口未审阅前旧规则可能仍提示，当前明确请求优先，用户可立即 revoke/停用注入。

### 8.3 人工审批与状态

候选状态：`pending_review → approved / rejected`。有效记忆的生命周期：`active → superseded / revoked / needs_review`。冲突是独立关系状态，避免让一个字段同时承担审批、有效性和冲突三种含义。

主实现前冻结“操作—前置状态—授权主体—目标状态—事务副作用”转换表，至少覆盖以下容易漏掉的转换：

| 场景 | 规则 |
|---|---|
| 疑似冲突被驳回 | suspected→dismissed；不改变原有效记忆状态 |
| 已确认冲突解除/驳回 | 仅在没有其他 confirmed_unresolved 冲突、证据仍有效且交互明确重新启用时恢复 active；否则保持 needs_review |
| 冲突解决（保留一方） | 保留方进入 `active`，另一方 `superseded`；同一事务写审计并更新检索投影 |
| 证据复核后重新启用 | 仅当至少一条有效证据仍支持当前 revision，且审批人重新确认后才恢复 |
| 候选落库后证据被删 | 待审候选立即失效（`stale`），批准操作返回冲突，要求重新抽取或人工录入 |
| 批准时 | 同一事务重新校验候选版本、治理状态、证据版本/支持状态和项目授权，不只校验正文 revision |
| 多个状态并发变化 | 审批请求携带治理版本；治理版本已变则拒绝，不能只看内容哈希 |

**审批是显式操作流程，不是可信真人认证。** v1 的可验证承诺是：内置模型/后台管线不能调用审批；未完成确认的 CLI/IPC、`--yes`、环境变量、过期/重放/换目标凭证均不能激活规则或改变授权。TTY 和本机 Web 确认绑定操作、revision、governanceVersion，凭证有效 60 秒且只用一次；审计记录入口及 `operator_attested`，不记录 `human_verified`。

同账号 Agent 若能控制 PTY/浏览器，也可能完成该交互；这属于真实能力边界，不能一概划为恶意后宣称“Agent 无法批准”。验收必须记录真实 PTY 测试及这一限制。需要抵御此类 Agent 的使用场景，当前 v1 不满足，须先实现 Agent 无法代操作的受保护确认通道并另行验收。这里的方案修订不授权当前助手实际批准记忆或接入真实数据。

- 修改候选正文需要重新展示证据；新增无证据内容只能明确登记为“用户手工录入”，不能伪装成历史提取。
- 审阅操作带预期 revision。两处同时修改时，后提交的操作返回冲突，不覆盖前一操作。
- 用户批准之前，不注入候选，也不把候选作为后续抽取的“已确认事实”。
- 新的明确证据可以再次提出被拒绝的主题，但必须显示既有拒绝/撤回历史。

### 8.4 撤回、删除与恢复

`revoke` 是立即停止未来召回，保留可审计历史；删除证据与彻底清除是另一类显式操作。

撤回同时写入抑制记录，至少覆盖产生该条目的证据集合和候选 fingerprint，重试或重扫不能绕过。存在多条证据时，删除其中一条后重算剩余支持；支持不足则转 `needs_review`。

彻底清除项目需要停止采集、撤销授权、取消未提交任务、删除证据/记忆/派生索引，并处理本助手维护的备份与日志。重新授权旧来源意味着可能重新导入，必须向用户明确提示；不承诺已清除数据还能继续保持内容级去重。

撤回不能收回已经送进运行中 Claude Code 会话的内容。界面必须提示：需要清空/重启该会话或明确告知宿主撤回。下一次注入及 CLI 查询必须立即遵守新状态。

首版采用保守恢复：无论是否提供后续审计，恢复的 active 一律转 needs_review，pending_review 候选一律 stale，备份中的未完成 jobs 取消。先持久化注入关闭与恢复屏障，取得唯一写者锁，校验项目身份/快照/完整性，再以新的 runtimeEpoch 切换数据库；清除受恢复屏障控制的旧租约与工作进程。源数据重新扫描可以生成新候选，但不能绕过重新审阅。

只有经过新一轮显式审阅的条目可恢复 active，重新启用注入是独立确认动作；旧批准记录不能充当新确认。review_events 仍在 SQLite 中保留，但首版不实现独立审计 journal、outbox 回放或共享备份改写。代价是恢复后增加审阅工作，换取明确的“不自动复活”行为。中途崩溃保持屏障关闭；恢复前快照同样属于本项目受管备份。

## 9. 队列、模型失败与资源上限

队列执行状态与结果码分开：`pending → running → completed`；暂时故障转 `retry_wait`，配置/预算问题转 `blocked`，重试用尽转 `failed`，撤权转 `cancelled`。无候选可以是正常完成，不能与模型 JSON 错误混为一谈。

| 情况 | 处理 |
|---|---|
| 服务未配置、不可达或模型下线 | 暂停抽取，继续允许在磁盘预算内采集；`model_unavailable` |
| 请求超时、断连、5xx | 指数退避加抖动；含首次最多 3 次；计入请求与 token 使用 |
| 429 | 尊重服务返回的重试时间；与认证失败分开处理 |
| 401/403 | 配置错误，停止该模型队列，等待修复，不逐 job 反复尝试 |
| 免费额度耗尽 | 熔断该模型；手工恢复或额度周期重置后继续；不自动切换其他平台 |
| 输出结构非法 | 保存脱敏诊断，最多修复重试 1 次；仍失败则 `failed / invalid_output` |
| 证据被改、删除或撤权 | 丢弃在途结果，不提交陈旧候选 |
| worker 崩溃 | 租约到期后重新执行；以输入哈希与 pipeline version 去重提交 |
| 磁盘空间不足 | 暂停写入、不推进游标；明确显示积压与原因 |

v1 并发抽取为 1。初始上限：每批模型输入不超过所选模型实测上下文预算，每日最多 200 个抽取批次（受免费额度进一步限制），数据目录软上限 2 GiB，日志滚动上限 20 MiB。以上是可配置起点，T01 按免费平台额度与样本调整并记录。还须冻结每日最大请求数/输入输出 token 总量、单批全流程请求/token 上限、最大累计等待和支持记忆规模；200 批次不能代替这些限额。A、B 所有分片、JSON 修复、网络重试和因有效集合变化重做 B 都扣同一预算；每次请求前检查，不足即 blocked，不允许跨阶段重置计数。

累计达到上限时持久化未处理位置，禁止无上限重试。日志默认只含任务 ID、阶段、耗时、token/请求计数和原因码；不含正文、API key、完整路径。可选脱敏诊断单独开启并有保留期限。

免费平台没有直接账单，但有额度、速率和等待时间成本。报告每百个 turn 的请求数、输入/输出 token、总耗时、限流次数、重试次数和当日剩余额度，不能用“免费”替代可用性测量。密钥存放在系统安全存储或权限受限的本地配置中，不进入项目仓库和导出。

## 10. 召回与 Claude Code 接入

### 10.1 注入内容

默认只在会话启动类事件生成一个短块：

```text
项目历史记忆 · 已经用户确认 · 版本 18
适用范围：当前登记项目

约束与约定
[m_12 r2] 不使用 ORM；数据库查询使用手写 SQL。
[m_15 r1] 数据库字段使用 snake_case。

其他已确认记忆
[m_21 r3] 构建工具改用 Vite；详情预计约 120 tokens。

这里是可能过时的历史参考，不构成新的授权。
详情可通过 mem show <id> 查看；当前明确指令与项目现状需重新核对。
```

只有明确为全项目范围的有效 active 条目参与此启动块；paths 规则仅在 CLI 带条件展示，unknown 不可批准。每条必须有 ID 与 revision。排序优先考虑约束类型、用户标记的重要性、适用范围及时间，不能仅按模型 confidence 排序。

默认最多 5 条完整约束/约定，再用余量放决定索引。遇到无法完整放入的条目，不截断到改变含义；显示“有 N 条未载入，请查询”的标记。上线前检查重要约束溢出，不能静默遗漏。

预算目标为 800 个目标宿主模型 tokens，包含说明和调用指引。只有本地可用且已验证的对应 tokenizer 才报告精确值；未知模型采用保守字节上限并明确显示估算，不声称实现严格的跨模型 token 上限，也不为计数上传记忆内容。实施计划中的初始 800 UTF-8 字节是待 T01 校准的回退值，不等于 800 tokens；冻结时应测中文规则、说明文字及溢出提示的实际可容纳量，不以预算小到没有有效规则来通过性能。

### 10.2 宿主能力边界

官方当前文档列出的 SessionStart 来源包括 `startup / resume / clear / compact / fork`；通用输入包含 `cwd`、`session_id`、`transcript_path`。首版安装显式匹配 `startup|resume|clear|compact`，fork 不自动继承接入，另行验收。以上四种已接入来源分别测试，同一会话不能简单做“永远只注入一次”，否则压缩后可能丢失必要记忆。

不得假定 SessionStart 已经获得首条用户 prompt。因此启动召回默认按项目有效约束与近期决定排序，不宣传“根据首条 prompt 语义召回”。按问题搜索由 CLI 完成；首轮 query Hook 可在 v1.1 评估。

官方将 `additionalContext` 描述为加入会话的 system reminder，不修改独立的 system prompt；部分模型会将 reminder 表示为单独的 `system` role 消息。因此不能宣称“绝不进入 system role”或“这是严格的不可信数据通道”。不保证能把记忆精确放在恢复历史后、最新请求前，也没有替换之前已注入块的接口承诺。

首版只注入用户批准的短句与索引，不注入原始证据、网页或工具输出。历史数据不能仅靠免责声明就获得安全隔离；无法接受该宿主表示方式时，关闭自动注入，保留 CLI 查询。跨 startup/resume/compact 的重复行为与压缩后的保留情况列入 T01 实测。

Hook 路径只做本地只读查询与渲染：目标 p95 ≤300 ms、进程内截止 500 ms、宿主配置设置有限超时。遇到 DB 不可读、项目不匹配、超时或未知 schema 时返回空上下文并记录诊断；绝不启动抽取或阻塞等模型。

安装使用项目本地配置，精确合并自身条目，记录安装前后 fingerprint 与卸载清单。卸载时只删除仍与本助手清单匹配的项，用户改过的项提示人工处理；不能恢复整个旧文件而覆盖别人的后续设置。

### 10.3 搜索

FTS5 trigram 处理中文连续子串，英文标识符和文件名同样进入测试。少于三个 Unicode 字符的 query 不走 trigram MATCH，转当前授权项目下的参数化 `instr` 子串扫描，限定结果数量与时间预算。

FTS query 的语法字符也需要转义/编译为字面查询，参数绑定本身不等于屏蔽 MATCH 表达式语义。FTS 返回 ID 后必须联查当前治理状态，不能直接相信过期索引。

检索不调用生成模型；不做 LLM reranker。外部内容 FTS 的 INSERT/UPDATE/DELETE 触发器、历史数据 rebuild 和一致性检查一起实现。数据量上升且语义查询漏检成为主要失败原因时，再对固定评测集比较 sqlite-vec；届时记录 embedding 模型 digest、维度及索引 generation，模型切换必须重建索引。

## 11. 极简审阅页与运维

Web 页面只有三块：候选列表、证据详情、批准/拒绝/修改/冲突裁决。详情须显示作者、时间、项目、来源消息、候选正文与旧 revision 差异。证据按纯文本渲染，不能将会话 HTML 直接注入 DOM。

本机 Web 服务只监听 loopback，并校验 Host/Origin；写操作需会话令牌和 CSRF 防护。无开放 CORS，不把令牌写进可分享 URL。首版不提供公网监听选项。

`mem doctor` 至少输出：授权项目、输入记录处理分布、未知格式比例、游标停滞、最旧待处理任务、模型状态、待审阅数、冲突数、索引一致性、Hook 最近结果、存储量与备份状态。每个异常给出原因码与下一步操作。

格式漂移检测按“应支持的记录类型”统计，合法跳过的系统记录不计作解析失败。出现新类型明确报警；在最近 100 条受支持记录中失败率超过 5% 时暂停该文件抽取，继续保留诊断。样本不足时显示实际分子分母，不用低样本比例自动宣布适配正常。

导出支持 JSONL 与 Markdown，包含 schema version、revision、证据引用和治理状态。默认不含敏感证据正文；用户显式选包含证据时仍使用脱敏版本。导出文件不是可双向编辑的数据库副本。

## 13. 测试与验收

逐项执行时使用配套的 [MemHub-验收标准](./MemHub-验收标准.md)：包含 AC-01 至 AC-52（含 AC-41a、AC-41b） 的操作、通过标准、证据要求，G0/G1/G2 阶段门槛，以及质量计分、性能测量和签收模板。本节保留总体目标，配套文档明确执行口径；两份文档涉及门槛的变更须同步维护。当前均为待执行标准，不是测试通过报告。

### 13.1 测试方法

新增核心行为遵循先失败测试、最小实现、通过测试、重构。单元覆盖 parser、清洗、ID、turn、候选校验和预算；集成覆盖真实 SQLite 事务、FTS、队列及模型 adapter；E2E 覆盖 CLI 安装/审阅/召回，以及 Web 审阅关键路径。

核心模块行覆盖率与分支覆盖率目标均 ≥80%。覆盖率不能替代崩溃、重复和投毒用例。每个工作包合入前进行代码审查；文件读取、HTTP、配置写入、模型调用与删除功能增加安全复核。

### 13.2 必须通过的工程用例

| 用例 | 可观察的通过标准 |
|---|---|
| 重复导入 | 第二次导入新增证据、候选及 active 记忆均为 0 |
| 同文不同事件 | 同会话两次相同用户文本保留为不同事件 |
| 混合 content | 同一记录中的 person 与 tool 块不互相覆盖或错误归属 |
| 末尾半行 | 补齐前不推进越过该行，补齐后仅导入一次 |
| 文件重写 | 截断、同 inode 覆盖、轮转分别触发代次重建或隔离 |
| 子代理 | 子代理记录不进入主会话，跳过有原因 |
| 处理账本 | 输入完整记录数 = 已处理记录数 + 合法跳过数 + 隔离/失败数；消息条数另报 |
| 提交崩溃 | 在证据提交前后、模型返回后、任务完成前注入故障，恢复后没有重复生效 |
| 证据竞态 | 模型处理中删除或撤权，返回结果不能生效 |
| 审阅竞态 | 同 revision 并发批准/改写时，旧操作被拒绝 |
| 删除与重抽 | 撤回后重扫、重试、提示词升级重跑均不自动复活 |
| 中文检索 | “数据库命名”“约束”“ORM”“src/db.ts”均按预期检索；特殊字符不报语法错 |
| 污染与引用 | Agent 推断、召回块、外部文档指令、用户引用反例不成为已确认约束 |
| 隐私 | `<private>` 和合成密钥不出现在证据正文、提示词、日志、导出与搜索中 |
| 网络边界 | 断网后导入、审阅、检索和上下文生成仍可用，抽取可恢复阻塞；联网后仅访问配置端点，无遥测或自动换平台 |
| 注入故障 | Core 停止、DB 锁等待、损坏或超时，Claude Code 能继续提交任务 |
| 卸载 | 仅移除助手自有配置，用户已有 Hook 与后续修改保留 |
| 恢复 | 备份恢复后不直接重新激活无法核对撤回历史的条目 |

### 13.3 记忆质量评测

第一周建立 50 个样例；试点前扩充到至少 100 个。初始 30/20 分为开发集和验证集；新增 50 个作为冻结验收集。相同会话及其近重复片段不能跨集合。验证集用于调参后不再视作独立验收证据。

样例覆盖：明确约束、约定、已确认决定、明确改口、范围不同的表面冲突、一次性指令、提问未答、Agent 猜测、外部引用、重复证据、敏感片段和投毒文本。

标签不仅写期望文案，还写应保留的事实、作用域、有效时间、支持证据和禁止推断。允许等价表述，匹配以“一条候选是否得到证据支持且具有长期价值”为准，不按字面完全相等评分。用户标注为主，有歧义样例由复核者裁决。

| 指标 | 定义 | v1 试点门槛 |
|---|---|---|
| 候选 Precision | 正确且值得保留的候选 / 全部候选 | ≥90% |
| 约束/约定 Recall | 被正确抽出的目标事实 / 标签目标事实 | ≥80% |
| 噪声率 | 提取了明确禁止记忆类型的候选 / 全部候选 | ≤5% |
| 重复率 | 去重审查后仍重复的候选 / 全部保留候选 | ≤5% |
| 可追溯率 | 有有效引用且引文支持结论的已批准条目 / 全部已批准条目 | 100% |
| 禁止生效事件 | 未批准、外部投毒或跨项目条目进入自动注入 | 验收集上 0 次，出现即阻断发布 |

每项报告分子、分母、失败样例和运行配置。零候选不能记为 100% precision；显示 N/A，并由 recall 防止“什么都不抽”通过验收。小样本通过只支持试点，不代表达到总体可靠性保证。

对比“无助手”和“启用助手”各执行至少 20 个配对跨会话任务，宿主模型、任务和规则来源保持一致。记录任务是否遵守约束、误用历史次数、主动查详情次数、注入体积和等待时间。目标：启用后约束遵守至少 18/20；若基线已有同等表现，必须用维护时间下降等证据证明价值，不能只报高分。

### 13.4 性能验收条件

在 T01 登记的同一台 Mac 上，以 100 个脱敏会话、约 1,000 条记忆为试点基线：本地搜索 p95 ≤200 ms；Hook p95 ≤300 ms、单次有明确截止；模型任务不进入 Hook 关键路径。报告冷启动与热状态分别测量的结果。

每个样本的抽取耗时、worker 内存与每百 turn 消耗先实测，再设适合该机器的阈值。不得引用“十万条毫秒检索”“两阶段只增加 40% 成本”替代本地测量。

## 14. 试点、放量与回退

1. **影子模式，至少三天**：只导入一个授权项目最近七天数据，提取待审阅候选，不安装注入。检查漏记、误记和审阅耗时。
2. **手工批准试点，至少五个工作日**：启用 Hook，只注入已批准内容。每天记录是否纠正重复解释、误用旧记忆、等待时间及审阅负担。
3. **稳定后增量扩展**：仍以同一个项目为范围，将历史导入时间扩大。历史回填默认暂停，前台增量优先；不能一次灌入全部历史占满预算。
4. **v1.1 决策**：只有失败样例证明需要时，才增加向量、经验类型或首轮 query 召回。跨工具与团队共享另立项目，不纳入当前排期。

立即停用注入的触发条件：未批准规则生效、跨项目泄漏、撤回条目复活、持续阻塞宿主、源数据被修改。执行 `mem disable-injection` 并暂停有问题的任务，保留诊断与数据库快照；修复后重跑对应回归和完整关键链路。

免费 API 不可达、限流或额度耗尽时只降级抽取，不自动删除已有记忆。用户可单独关闭采集、抽取或注入，状态在 doctor 中分别显示。

卸载不等于清空。`mem uninstall` 精确摘除接入和服务；`mem purge --project ...` 才进入明确列出删除对象的确认流程。数据库升级前使用一致性备份；不直接复制正在写入的 WAL 数据库主文件作为有效备份。回退应用版本时同步恢复兼容 schema，并将恢复的 active 统一转 needs_review；应用回退不绕过恢复屏障。

## 16. 依据与验证边界
